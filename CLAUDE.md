# LINEA — студия дизайна интерьера с ИИ-конвейером

Сайт студии + автоматический генератор дизайн-проектов: клиент заполняет бриф (размеры, фото, стиль) → конвейер собирает папку проекта (планы с мебелью, развертки каждой стены, потолки со светом, концепция, спецификация материалов, смета).

## Только квартиры (решение 06.11.2026)
Сайт предлагает ТОЛЬКО дизайн-проекты квартир. Дома, коттеджи, ландшафт, «лестница/по этажам», срок «дом — до 72 ч» на сайт не пишем.
Переключатель — `tools/site-shell.js` → `TERMS.houses = false` (генераторы и `gost-facts.js` по нему отбрасывают альбомы домов);
старые адреса домов → `TERMS.moved`, заглушки пишет `node tools/gen-moved-pages.js` (noindex + переход, папки альбомов домов убирает).
`sync-gost-releases.sh` дома не переносит. Движок домов (engine/, examples/house-brief.json, ландшафт) не удалён — это внутренний инструмент.

## Структура
- `engine/generate.js` — генератор папки проекта (Node, без зависимостей). Запуск: `node engine/generate.js <brief.json> <outdir>`
- `engine/presets.js` — 6 стилей, тарифы, расценки работ и мебели
- `site/` — статический сайт: index.html (лендинг с hero-фильмом по прокрутке), brief.html + js/brief.js (визард брифа), portfolio/demo/ и portfolio/dom-120/ (демо-проекты, генерируются движком)
- `site/assets/frames/` — раскадровка hero (до 11 кадров 1280 px + manifest.json); пересобирает `node tools/gen-home.js` — только кадры, сверенные с планом и подписанные дизайнером
- В каждой папке проекта движок пишет три входа: `presentation.html` (листалка альбома для клиента), `index.html` (все файлы) и `print.html` (источник единого PDF)
- `examples/demo-brief.json` — эталон схемы брифа (размеры в метрах; стены A/B/C/D = верх/право/низ/лево; конструктив: `object.structure {houseType, extWall, intWall, slab}`, `object.bearing[]`, `object.risers[]`, `room.walls`; перепланировка: `object.demolish[] {from,to,thick,h,kind,note,level}` — сносимые участки, `object.partitions[] {from,to,type,thick,h,note,level}` — возводимые перегородки, `type` = `gkl|block|brick`; координаты отрезка — ось конструкции в метрах, толщина откладывается на две стороны, как у `object.bearing`)
- `examples/fixtures/*.json` — краевые случаи для регрессий: студия 24 м², Г-образная, панель с несущими и стояками, заведомо кривой бриф
- `examples/house-brief.json` — второй эталон: дом 120 м² в два этажа (`rooms[].level`, `rooms[].stairs`)
- `clients/<slug>/` — рабочие папки клиентов (brief.json, отчёты, project/)
- `.claude/agents/` — 7 агентов конвейера; `.claude/commands/` — /new-client, /regen, /qa-project
- `.claude/skills/cad-drawings` — канон рабочих чертежей (состав альбома, лист А3, слои, размеры, обозначения, чек-лист приёмки)
- `docs/` — маркетинг- и SEO-планы

## Инструменты выпуска
- `node engine/generate.js <brief> <out> [--date=ДД.ММ.ГГГГ] [--strict]` — `--date` (или `meta.issueDate` в брифе) даёт побайтово воспроизводимый альбом; `--strict` не собирает проект, если валидатор нашёл ошибки в брифе.
- `engine/validate.js` — проверки брифа (нахлёст помещений, проём за стеной, Σ площадей vs `object.area`, высоты). Ошибки и предупреждения печатаются в консоль, попадают в `manifest.json` и в документ `00-pasport/zamechaniya.html`.
- `node tools/regen-fixtures.js [--update] [--only=имя]` — снапшот-фикстуры: гоняет движок по 6 эталонным брифам (`examples/fixtures/`) с датой 01.01.2026 и сверяет sha256 каждого файла. Любая правка движка, изменившая лист, видна здесь. Запускать до и после правок; `--update` — принять новый вывод эталоном (сначала посмотреть листы глазами).
- `node tools/lint-sheets.js <папка-проекта>` — линтер бумаги: формат A3, наличие штампа и масштаба, кегль ≥ 2,5 мм (ГОСТ 2.304), перо ≥ 0,18 мм.
- `node tools/audit-sheets.js <папка-проекта> [--type=elevation] [--json]` — аудит СОДЕРЖАНИЯ листов по канону `docs/cad-canon.md`: цепочки размеров и их замкнутость, отметки уровня, привязки, легенды, спецификации, примечания, масштаб из ряда ГОСТ. Тип листа движок пишет в `data-sheet`, смысловые блоки — в `data-el`.
- `node engine/generate.js <brief> <out> --mono` — ч/б выпуск для печати на офисном лазернике: палитра переводится в серую шкалу по яркости с гарантированным контрастом (смысловые слои уходят в тёмный серый), в штампе появляется пометка «ч/б». Готовый файл: `./tools/album-mono.sh <brief.json> [выходной.pdf]`.
- `node tools/gen-style-pages.js` — страницы стилей сайта (`site/style/`): хаб + 6 страниц из `engine/presets.js` (палитра, отделка, артикулы, цена материалов по тарифам) и обновление `sitemap.xml`. Редакторские тексты (кому подходит / на чём не экономить / FAQ) живут в `COPY` внутри самого скрипта. Пересобирать после правки пресетов стилей.
- `node tools/gen-site-pages.js` — внутренние страницы сайта: `cases/` (хаб + 2 кейса на демо-проектах), `compare/` (сравнение с рынком, пакеты, тарифы), `stories/` (хаб + 2 разбора), `reviews/`; обновляет `sitemap.xml`. Контент и вёрстка живут внутри скрипта; правило раздела — только то, что подтверждается файлами проекта. Отзывы не выдумываем: пока тест не дал завершённых проектов, страница показывает механику сбора, а не цитаты.
- `node tools/gen-articles.js` — журнал (`site/journal/`): хаб + 5 статей по документации (состав альбома, развёртки, электрика и зоны ПУЭ, пирог пола, смета). Тексты в массиве `ARTICLES` внутри скрипта, у каждой статьи оглавление, Article + FAQPage, перелинковка на кейсы, сравнение и настоящие листы демо-альбома.
- `node tools/gen-catalog.js` — каталог услуг (`site/catalog/`): хаб + 6 позиций (проект квартиры, проект дома, только рабочая документация, планировочное решение, визуализации, смета и комплектация). Состав по листам, сроки, шаги, FAQ, микроразметка Service + Offer.
- `tools/site-shell.js` — **единственный источник шапки, подвала, липкой панели и списка разделов** (`SECTIONS`) плюс автор и версия CSS. Добавили раздел сайта — правится только этот массив.
- `node tools/sync-static-nav.js [--check]` — переносит шапку и подвал из каркаса в статические `index.html` и `brief.html` (они не проходят через генераторы). С `--check` только сообщает о расхождении и возвращает код 1 — годится для проверки перед коммитом.
- `node tools/gen-info-pages.js` — служебные страницы: `about/` (автор, метод «человек против конвейера» таблицей, границы услуг), `contacts/` (каналы связи, что подготовить, условия) и `404.html` (ссылки абсолютные — страница отдаётся с любого пути).
- `node tools/gen-more-pages.js` — остальные страницы: `portfolio-hub/` (карточки 9 проектов нового формата — новые первыми, старые демо внизу как «первая версия (2025)»), `process/`, `price/` (+калькулятор листов), `faq/`, `policy/`, `sitemap/`, `checklist/` (печатный чек-лист приёмки, 24 пункта) и `thanks/` (noindex). Запускать ПОСЛЕ `gen-gost-pages.js`: карточки проектов он читает из `portfolio/<slug>/_card.json`, число листов — из `sheets.json`. Коэффициенты калькулятора (листы ≈ b + k×помещений, +этаж, развёрток на помещение) и диапазоны листов квартиры/дома считаются из выпусков при сборке — руками не пишутся. Квиз выбора услуги — в gen-catalog.js. Демо-альбомы старого движка (`portfolio/demo`, `dom-120`): 30 и 56 листов.
- Визуализации на страницах проектов `portfolio/gost-*`: `gen-gost-pages.js` сам копирует их из `~/projects/gost-draft/projects/<объект>/renders` (связка объект → слаг — строки `sync_one` в `sync-gost-releases.sh`) в `site/assets/portfolio/<slug>-hero.jpg` (1600 px) и `site/assets/portfolio/<slug>/` (лента, 1200 px). **Статус кадра решает приёмка движка** — вывод `node tools/views-check.js <project.json>` в gost-draft: `signed` (сверен с планом по чек-листу и подписан дизайнером), `prelim` (сверен исполнителем, ждёт подписи); остальное (не совпал с планом или сверялся только «по глине») на сайт не идёт. В ленту и заглавный кадр — только signed и prelim, под каждым кадром статус; «визуализаций» в карточках и счётчиках = только подписанные. Нет сверенных кадров — заглавным идёт лист расстановки мебели. Если движка рядом нет, берётся `_renders.json` с сайта. Выпуск, чьи листы закоммичены до 23.10.2026 (до разбора практика), получает плашку «Выпуск до разбора замечаний практика» (`preReview()`); после перевыпуска она исчезает сама.
- **Условия работы — один источник: `tools/site-shell.js` → `TERMS`** (решение 27.10.2026: «открытый бесплатный тест» закончен, проект начинается после оплаты). Цены `PRICES` (рубли; `null` — «стоимость называем после брифа, до начала работы»), кругов правок `ROUNDS`, реквизиты исполнителя `REQUISITES` (null — пометка «будут указаны до приёма первой оплаты»), фраза про «ПРЕДВАРИТЕЛЬНО», что не входит. Цены дублируются в серверном `linea-private/config.php` (копейки) — менять оба. schema.org Offer выводится только при заданной цене; «0 ₽», «бесплатно», «без предоплаты» на сайте не пишем. Юридические страницы — в `gen-more-pages.js`: `policy/`, `soglasie/` (согласие на ПДн, редакция `LEGAL_ED`; та же дата в brief.js → `client.consent.edition`), `oplata/`, `oferta/` (черновик: noindex и вне sitemap, пока `OFERTA_DRAFT = true`). В брифе — обязательная неотмеченная галочка согласия (без неё brief.js не пускает дальше, `api/brief.php` отвечает отказом) и необязательная «можно показать в портфолио»; сервер пишет в заказ текст согласия с редакцией, временем и флагом портфолио.
- **Розетки и электрика (03.11.2026):** страница `rozetki/` и блок `<!-- home:rozetki -->` на главной берут числа (марки розеток, выводы, группы щита, высоты, строки кухни) из листов альбома через `tools/rozetki-facts.js` (по умолчанию `gost-kv3k`; `node tools/rozetki-facts.js [слаг]` — посмотреть факты). Раздел «Лист против картинки» — `compare/#list-vs-kartinka`; строки «Зачем» у разделов альбома — `SECTION_WHY` в `gen-gost-pages.js`; таблица «сами / своя бригада / через LINEA» на `/remont/` — `PATHS` в `gen-brigady-pages.js` (условия только из `BRIG_TERMS`).
- **Разговор до оплаты — `TERMS.call`** (site-shell.js): `channel: null` → «свяжемся по почте или телефону из брифа»; задать канал (`{ title, href }`) — и он появится на order.html, в кабинете и в брифе (`sync-static-nav`). Сроков ответа там не обещаем.
- `node tools/sync-static-nav.js --only=brief.html` — синхронизировать один статический файл (главную правит отдельный шаг).
- `node tools/touch-sitemap.js` — проставляет `<lastmod>` каждому адресу sitemap.xml по mtime соответствующего html-файла. Запускать ПОСЛЕДНИМ, после всех генераторов.
- `node tools/check-sheets.js <папка-проекта> […]` — сквозная проверка выпуска поверх аудита и линтера: дубли атрибутов и NaN в разметке, формат листа, честность штампа (масштаб, «Лист N из M», сквозная нумерация без дыр и повторов), выход надписей за поле чертежа и наезд на основную надпись, формат отметок ±0,000, слишком пустые листы.
- `node tools/check-overlap.js <папка-проекта> [ещё…]` — **наложения подписей, из командной строки**. Входит в контур приёмки наравне с `check-sheets`: возвращает код 1, если хоть одна пара надписей налезла. Шесть проектов проверяются примерно за 6 секунд. Под капотом поднимает статический сервер из `site/`, гоняет `_dev-overlap.html` в headless-браузере с `--dump-dom` и читает машиночитаемый итог из `<script id="result">`. Зависимостей нет, протокол отладчика не используется. Браузер на наших альбомах печатает DOM и не выходит (та же болячка, что у `album.sh`) — поэтому скрипт читает поток и снимает группу процессов сам.
- Та же проверка глазами: `http://localhost:8141/_dev-overlap.html?p=portfolio/demo`. Наложения ловятся только браузером — нужны настоящие метрики шрифта: сравниваются `getBoundingClientRect()` всех `<text>`, а `getBBox()` не годится, он игнорирует трансформацию группы содержимого. Один лист по-прежнему смотреть в `_dev-view.html`.
- **Кэш браузера врёт.** И страница, и CLI гасят кэш меткой прогона: без неё проверка показывает прошлый выпуск и «не замечает» правок движка — на этом 01.10.2026 едва не проехала регрессия.
- `node tools/gen-home.js [--check] [--force]` — **главная на материалах альбомов GOST-DRAFT** (27.10.2026, после разбора практика). `index.html` — ручная вёрстка, генератор переписывает только области `<!-- home:имя -->…<!-- /home:имя -->`: фильм hero (кадры только с подписью дизайнера по `views-check.js` и новее разбора 22.10.2026 → `assets/frames/`, `manifest.json`, `hero.jpg`, `og-home.jpg`), карточки портфолио (визуализация только «подписан», иначе лист расстановки мебели; «предварительно: N вопросов к заказчику»), плитки «Листы как есть» (лист ищется по имени без номера в `sheets.json`), стены помещения рядом с листом плана, условия/FAQ/микроразметку из `TERMS`, плашку и воронку из каркаса. В конце проверяет, что каждый локальный `src`/`href`/`srcset` главной существует (код 1; `--check` — только проверка). Запускать после `gen-gost-pages.js`, затем `sync-static-nav.js --only=index.html`. Текст вне меток правится руками. `make-frames.sh` — переходник на него.
- `./tools/album.sh <папка-проекта>` — единый `album.pdf`: титул → оглавление со ссылками → документы → все листы A3 (печатает `print.html` headless-браузером).
- `LINEA_DEBUG_FIT=1 node engine/generate.js …` — печатает по каждому листу габарит содержимого, выбранный масштаб и процент заполнения поля.

## Ландшафтный контур (участок вокруг дома)

Второй конвейер репозитория: тот же бумажный канон, но предметом является участок, а не интерьер.
Интерьерный движок (`engine/generate.js`) он не трогает намеренно — у того побайтовые снапшот-фикстуры.

- `node engine/landscape.js <brief.json> <папка> [--date=ДД.ММ.ГГГГ] [--mono]` — альбом ландшафтного
  проекта: 20 листов A3 + пояснительная записка, ведомости, смета, график работ, регламент ухода,
  `index.html` / `presentation.html` / `print.html` / `manifest.json`.
- `engine/paper.js` — бумажный слой: лист A3, рамка, основная надпись, подбор масштаба по габариту,
  нормализация пера и кегля. **Кегли и толщины задаются в «бумажных» единицах** (font-size 10 ≈ 2,6 мм
  на листе) и не зависят от масштаба. Панели (`panel`) и подвалы (`footer`) рисуются ВНЕ масштабируемой
  группы: иначе таблица растягивается вместе с планом и масштаб в штампе перестаёт быть правдой.
  Заголовок листа (`P.title`) тоже уходит в бумажный слой — его длина не должна влиять на масштаб плана.
- `engine/land-layers.js` — условные обозначения: границы, здания, покрытия, дорожки, деревья,
  кустарники, изгороди, цветники, светильники, дождеватели.
- `engine/land-sheets-a.js` / `-b.js` — листы альбома (опорный план, зонирование, генплан, разбивочный,
  покрытия, вертикалка, дендроплан, посадочный, ведомости, цветники, фрагменты, свет, полив, узлы, вид).
- `engine/land-plants.js` — каталог посадочного материала (латынь, размер, цена, высота, свет).
- `engine/land-bom.js` — площади по фактической геометрии (растр 0,1 м), ведомость растений и смета.
  **Смета считается от чертежа**: правка брифа автоматически меняет объёмы работ и материалов.
- `engine/land-validate.js` — проверка расстановки: наложения построек, покрытий, цветников и дорожек,
  отступы по СП 53.13330.2019 (6.7), ширина проходов, смыкание крон, высота посадок под ЛЭП,
  выход круглых элементов за границу, сходимость баланса площадей. Прогонять после каждой правки брифа.
- Клиентские папки — `clients/<slug>/brief.json` (исходные данные) и `clients/<slug>/project/` (выпуск).
  Просмотр: `.claude/launch.json` → `linea-client` (порт 8142), страница `clients/<slug>/_view.html`
  (`?f=01-genplan/04-genplan.svg` — один лист, без параметра — весь альбом).
- Проверки бумаги те же: `tools/lint-sheets.js` и `tools/check-sheets.js` (оба научены ландшафтным
  листам: панель/подвал вне масштабируемой группы, «б/м» в штампе у ведомостей).

## Раздел «Документация» — альбомы движка GOST-DRAFT

Рабочую документацию студия выпускает отдельным движком (`~/projects/gost-draft`, независимый репозиторий:
код не импортируется, общие только знания). На сайт попадает только результат — листы выпуска.

- `./tools/sync-gost-releases.sh [путь-к-движку]` — переносит выпуски: листы в `site/portfolio/<slug>/sheets`,
  служебную листалку выпуска — в `_release.html` (из неё генератор читает состав).
- `node tools/gen-gost-pages.js` — собирает `site/gost/` (как устроен и проверяется комплект) и страницу
  каждого альбома (состав по разделам, решения по объекту, все листы). **Числа — листы, блокеры, разделы —

## Публикация
Сайт публикуется на GitHub Pages из папки `site/` через Actions (`.github/workflows/pages.yml`).
**Достаточно `git push origin main` — ручной запуск не нужен и вреден.** Workflow слушает `on: push`
по ветке `main` без фильтра путей (фильтра `site/**` в нём нет — любой пуш в main запускает сборку),
плюс `workflow_dispatch`. У него `concurrency: group: pages` с `cancel-in-progress: true`, поэтому
**запуск, стартовавший позже, отменяет предыдущий**: привычная связка `git push && gh workflow run`
создаёт две сборки, одна из которых гасит другую. Отсюда и пошло давнее заблуждение, будто
push-события сборку не запускают — на деле их run просто отменялся ручным. Проверено 02.10.2026:
push без ручного запуска отработал `success`. Статус — `gh run list --workflow=pages.yml -L 1`,
сборка около минуты. Старая схема (`git subtree split --prefix site -b gh-pages` + Jekyll-сборка ветки) отменена: legacy-сборщик падал на альбомах в сотни SVG даже с `.nojekyll`. Живой адрес — https://alex1986-rgb.github.io/linea-design-studio/

## Правила
- Чертежи правятся ТОЛЬКО через код движка + перегенерацию, не руками в SVG.
- Кегли и толщины линий в модельных координатах нормализуются в `normalizeInk()` (бумажные мм). Не вписывай «магические» font-size/stroke-width под конкретный масштаб — они пересчитываются.
- Штриховки с запасом обрезай `clipPath`: `contentBox()` не измеряет содержимое обрезанных групп и `<defs>`, иначе лист уедет на ступень мельче по масштабному ряду.
- После улучшений движка перегенерируй демо: `node engine/generate.js examples/demo-brief.json site/portfolio/demo`
- Полный регламент конвейера — скилл `design-pipeline`; канон самих чертежей — скилл `cad-drawings` (читать перед любой правкой листов).
- Демо-проекты: `node engine/generate.js examples/demo-brief.json site/portfolio/demo` и `node engine/generate.js examples/house-brief.json site/portfolio/dom-120`.
- Сайт: премиальный тон, тёмная тема, дизайн-токены в `site/css/main.css`; на каждой странице canonical + OG + schema.org.
- Просмотр сайта: любой статический сервер из `site/` (движку сервер не нужен); конфиг превью — `.claude/launch.json` (имя `linea-site`, порт 8141).
- Смотреть отдельный лист: `http://localhost:8141/_dev-view.html?f=portfolio/demo/<путь>.svg` — обёртка нужна потому, что голый SVG браузерная панель рендерит мелко, а Chrome headless на этих файлах зависает.
