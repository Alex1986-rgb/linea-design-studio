# «Лист по запросу»: протокол очереди Beget ↔ воркер GOST-DRAFT (v1, 31.10.2026)

Бригада на своём объекте нажимает «Нужен лист» (кабинет `/brigada/` → Объекты → Листы по запросу): текст и/или голос
(Web Speech API — диктовка в текст; где его нет — запись MediaRecorder и загрузка аудио), помещение и стена — необязательно.
Запрос встаёт в очередь на Beget; листы выпускает движок GOST-DRAFT на SmartApe (воркер — отдельная работа), забирая задания
по этому протоколу. **В задании нет ПДн клиента**: номер заказа, слаг проекта, текст бригады, помещение/стена, язык.

## Где лежит очередь
- Истина — таблица `br_sheet_reqs` (SQLite или MySQL Beget, `server/api/lib/migrations.php`).
- Зеркало для глаз и отладки — `linea-private/sheet-requests/<id>.json` (то же, что отдаёт `a=get`), обновляется при каждой смене статуса.
- Аудио и готовые PDF — `linea-private/brigady/files/…` (вне веб-корня), отдаются только через PHP с проверкой прав.

## Статусы
`new` (принят) → `work` (воркер взял) → `ready` (PDF готов) · `question` (нужен уточняющий вопрос; бригада отвечает в кабинете →
снова `new`) · `rejected` (не лист: например, вопрос к договору). Задание в `work` дольше 2 часов само возвращается в `new`.
Бригаде на каждую смену статуса — письмо (если письма включены; тестовые записи — никогда) и статус в кабинете.

## Доступ воркера
- Адрес: `https://<домен>/api/sheets-worker.php` — **только https** (кроме `php -S 127.0.0.1` на маке).
- Заголовок `X-Worker-Token: <sheet_worker_token из linea-private/config.php>` (не `Authorization`: на Beget CGI он до PHP не доходит).
  Пустой токен в конфиге — API выключен (503). Неверный — 403.
- Лимит: 2000 запросов в час с адреса.

## Методы
| Запрос | Что делает |
|---|---|
| `GET ?a=next&limit=1..10` | взять до N заданий (`new` → `work`), ответ `{ok, tasks:[Task…]}` |
| `GET ?a=get&id=N` | задание целиком `{ok, task}` |
| `GET ?a=audio&id=N` | запись надиктовки (webm/ogg/m4a/mp3/wav), 404 если нет |
| `POST ?a=result` multipart: `id`, `file` (PDF, ≤ 30 МБ, проверяется сигнатура `%PDF-`), `note` | готово → `ready` |
| `POST ?a=question` JSON `{id, question}` | нужен вопрос к бригаде → `question` |
| `POST ?a=reject` JSON `{id, reason}` | не лист → `rejected` |
| `POST ?a=requeue` JSON `{id}` | вернуть в очередь (воркер упал) |

## Формат задания (Task, v1)
```json
{
  "v": 1,
  "id": 17,
  "status": "work",
  "order": "LN-2611-0001",
  "objectSlug": "prompt-kv54",
  "object": "Квартира 64 м²",
  "text": "Нужна развёртка стены B кухни с выводами под технику",
  "room": "Кухня-гостиная",
  "wall": "B",
  "lang": "ru",
  "audio": { "id": 51, "url": "sheets-worker.php?a=audio&id=17" },
  "question": "",
  "answer": "",
  "createdAt": "2026-11-01 00:28:05",
  "history": [ { "id": 12, "text": "…", "status": "ready" } ]
}
```
- `objectSlug` — слаг проекта GOST-DRAFT из пакета проекта (`tools/brigady-pack.mjs` пишет его в `pack.json`); по нему воркер
  находит `projects/<slug>/project.json`.
- `room` — название помещения из пакета (может быть пустым); `wall` — A/B/C/D (или кириллица А–Г), может быть пустой.
- `audio` — `null`, если бригада только писала текст; если `text` = «(голосом, см. запись)» — текст только в записи.
- `answer` — ответ бригады на прошлый `question` (задание вернулось в очередь).
- `history` — до 10 прошлых запросов по объекту (для контекста: «как в прошлый раз»).

## Ответ воркера
`POST ?a=result` — один PDF (лист или несколько листов в одном файле). В `note` — коротко для бригады: «Лист Р-7, масштаб 1:20,
пометка ПРЕДВАРИТЕЛЬНО — открытые вопросы К-3, К-5». Ответ `{ok:true}`; бригада видит «Готов» и ссылку на PDF.

## Лимиты со стороны бригады
10 запросов на объект в сутки, 30 на бригаду в сутки, не больше 5 открытых (`new`/`work`/`question`) на объект; запись — до 10 МБ;
только объекты в статусе «подписание договора» или «ремонт идёт».

## Проверка
`node tools/test-brigady.mjs` — шаг «11б»: создание запроса с текстом и записью, `next` с верным/неверным токеном, отсутствие ПДн
в задании, зеркало в `linea-private/sheet-requests/`, `audio`, `result`, статус «Готов» и скачивание PDF бригадой.
