# Отчёт: LINEA 2.0 — модель, магазины, комиссии (28.10.2026)

## Что сделано
- 4 исследователя: открытые движки (IfcOpenShell, Bonsai, Blender, FreeCAD, That Open, Pascal Editor, Sweet Home 3D, xeokit…),
  магазины и партнёрки РФ (ставки, фиды, программы для дизайнеров), источники 3D-моделей и данных сантехники/электрики,
  требования практиков и карта конкурентов (Remplanner, Planner 5D, Лемана, INMYROOM, Flatica, Профи).
- 2 критика: технический (по коду gost-draft) и бизнес/юридический.
- Итоговый план: `docs/plans/2026-10-28-linea-model-i-magaziny.md`.

## Ключевые выводы
- Клонировать проприетарное нельзя и незачем; открытое — библиотеками (IfcOpenShell LGPL, Blender GPL на сервере, Pascal Editor MIT позже).
  Sweet Home 3D Web (GPL) и xeokit (AGPL) — нельзя в закрытый продукт.
- Технический критик: `project.json` остаётся истиной; нужен общий `engine/scene.js`; «листы из IFC» вычеркнуты.
  Расхождение рендера с планом даёт ИИ-перерисовка, а не отсутствие модели → маски/глубина + автосверка.
- Сервер SmartApe без AVX2 и GPU: Blender 4.x/OIDN может не запуститься — проверить до планирования рендера.
- Бизнес-критик: комиссии ≈ 11–14 тыс. ₽ с проекта (не 30–60); основа — оплата проекта и комплектация как услуга 7–12 %.
  Порядок: сначала цены, ИП, приём оплаты и 3–5 клиентов; продукт с редактором — по замерам через 6 месяцев.
- Юридика: комиссии не на НПД; ссылки только в закрытых проектах; ПДн магазинам не передавать; права на фото/3D по договору.
- ГОСТ Р 21.101-2020 заменён ГОСТ Р 21.101-2026 (с 01.04.2026) — сверить ссылки в каноне движка (не проверено, что изменилось).

## Пилот «LINEA CAD» на Pascal Editor (28.10.2026, тот же день)

Выбор основы — 3 оценщика (Pascal / Bonsai+IfcOpenShell+FreeCAD / That Open+Sweet Home 3D) сошлись:
**Pascal Editor (MIT)** — редактор; **IfcOpenShell** — IFC-ядро для ArchiCAD/Revit; **Blender** — только серверный рендер;
Sweet Home 3D отпал (нет IFC, GPL-web), That Open — просмотрщик без авторинга. ArchiCAD код не клонируется
(закрытый, Graphisoft ушёл из РФ) — делаем функциональный «ArchiCAD под студию»: слои стен, параметрические двери
с проёмом/полотном, зоны, 2D+3D, IFC в обе стороны.

Сделано:
- Pascal склонирован на SmartApe `C:\pascal\editor` (коммит ae186c3), свой Node 24.22.1 `C:\tools\node-pascal`
  (системный 24.21 для GOST-DRAFT не тронут), Bun 1.4.4 baseline `C:\tools\bun` (процессор без AVX2).
- Запуск `C:\bat\pascal-up.cmd` (WMI, переживает SSH), порт 3002 закрыт снаружи правилом `Pascal-3002-block`.
  Смотреть: `ssh -L 3002:127.0.0.1:3002 smartape-win` → **http://localhost:3002** (не 127.0.0.1 — dev-режим Next не отдаёт ему скрипты).
- Конвертер `gost-draft/tools/to-pascal.cjs`: `node tools/to-pascal.cjs <project.json> [out.json] --post=http://127.0.0.1:3002`.
- modern-4k загружен: 19 стен (наружные 300 мм со сдвигом наружу, стыки сомкнуты), 9 дверей (проём и полотно раздельно),
  9 окон, 9 помещений, 38 предметов; 6 предметов без подходящей модели каталога пропущены.
  Снимки: `img/2026-10-28-pascal-modern4k-2d.jpg`, `img/2026-10-28-pascal-modern4k-3d.jpg`.

Дальше (по порядку):
1. Единицы в метрах (сейчас интерфейс показывает футы).
2. Электрика и сантехника: точки как предметы на стене с метаданными (в Pascal их нет).
3. Свой каталог: GLB + артикул/цена/ссылка в metadata; масштаб моделей под габарит изделия.
4. Обратный путь Pascal → project.json (правки дизайнера в редакторе → листы GOST-DRAFT).

6. Автозапуск на сервере при перезагрузке и сборка в продакшн-режиме вместо dev.

## Автоматизация LINEA CAD (28.10.2026)
- Форк: ветка `linea` в `C:\pascal\editor`, коммит «metric and millimeters by default» (метры/мм независимо от часового пояса).
- Рабочая сборка (`bun run build`, 9/9) вместо dev; запуск `C:\bat\pascal-up.cmd` → `next start -H 127.0.0.1 -p 3002`
  (наружу не слушает), база `C:\pascal\data\pascal.db` (`PASCAL_DB_PATH`), журнал `C:\pascal\server.log`.
- Мак: `linea-cad <проект>` — туннель + перенос + открыть; `--all`, `--list`, `--status`, `--stop`. Сцена `linea-<проект>`
  обновляется (PUT), не плодится. Проверено: modern-4k версия 1 → 2.
- **Не сделано:** задача автозапуска `PascalUp` (SYSTEM, при старте) — классификатор не дал создать её из сессии;
  скрипт лежит `C:\tools\pascal-task.ps1`, запускает Александр. До этого после ребута сервера — `C:\bat\pascal-up.cmd` вручную.
