## Находки (экран -> что не так -> важность -> как исправить)

### Кабинет клиента
1. Письма клиенту (код): брифа получен/сумма/счёт/оплата/выпуск альбома/вопросы/ответ на правки — НЕ уходят на почту. kab_notice() только пишет строку в «колокольчик»; письмо идёт лишь для кода, ручного сообщения админа, предложений бригад, этапа ремонта, договора. Настройки «письма по группам» и «сводка раз в день» (prefs.digest) сохраняются, но нигде не читаются. При этом в кабинете написано «Как будет готов — напишем на почту». БЛОКЕР. Сделать: kab_notice(...) с флагом mail по prefs + шаблон kab_notice; дайджест — в cron.
2. Бриф отправлен -> клиент без письма: brief.php вызывает kab_notice с account_id=0, а kab_notice при accountId<=0 выходит (return) — уведомления «бриф получен» нет вообще; письма-подтверждения нет. Остаётся только экран с токен-ссылкой. БЛОКЕР. Слать письмо «Бриф LN-… получен, сумма/срок ответа, ссылка в кабинет, что дальше» сразу.
3. Вход: клиент должен знать, что «код по почте» — а в письме с токеном ссылки нет; с моба код копируется вручную. Вход нужен только при действии/новом устройстве — ок. Важно: письмо кода уходит через mail() без SPF/DKIM-проверки в коде, и пока brig_mail_enabled=false (дашборд сам предупреждает) вход в кабинет невозможен вообще. БЛОКЕР запуска (конфиг). Добавить кнопку «выслать повторно через N с», запасной путь «написать в поддержку», ссылку-«волшебную» в письме.
4. Сроки: нигде нет «когда будет первый вариант» (только «делаем первый вариант…»). Нет плановой даты, нет ETA по шагу, нет «мы ответим в течение рабочего дня» с датой. ВАЖНО. Поле expected_at у заказа (ставит админ или считается от оплаты по тарифу) + строка в карточке и в письмах.
5. Таймлайн: полоса показывает шаг, но не историю («что было и когда»): есть «Лента заказа» (сообщения), но событий-статусов (оплата, выпуск, ответ на правки) в ней нет. ВАЖНО. Объединить notices+events в одну историю.
6. Мобильная вёрстка карточки заказа (скриншот proekt-375): залипшая кнопка «Открыть альбом (PDF)» перекрывает карточку «Оплата»; названия шагов полосы обрезаны («Первый вариант…»); вкладки Проект/Вопросы/Правки/Ремонт ужимаются. ВАЖНО. Дать липкой кнопке отступ снизу/в потоке; в полосе показывать только текущий шаг «Шаг 5 из 7».
7. Оплата: сумма и «Оплатить картой или СБП» есть; чек — «в письме сервиса онлайн-оплаты; копия в Документах» (нужна проверка, что копия реально лежит), реквизитов ИП/договора-оферты нет («будут указаны до приёма первой оплаты», оферта — черновик). Нет разбивки «за что 128 000 ₽» (метраж x ставка x тариф), нет условий возврата в карточке оплаты. ВАЖНО -> блокер для боевого приёма денег до реквизитов/оферты. Добавить расчёт («64 м2 x 2000 ₽») и ссылку на условия/возврат.
8. Вопросы К-N: варианты-кнопки и свой текст — хорошо; но нет прикрепления фото/файла к ответу, нет «пропустить с уточнением позже», нет срока ответа и последствий («пока не ответите — не выпустим финал»; помечено только «для финала»). ВАЖНО. Прикрепление фото к ответу, дедлайн, напоминание в письме.

Альбом: только «Скачать PDF» и ссылка на presentation; нет встроенного просмотра листов в кабинете, нет сравнения версий кроме списка «что изменилось», замечания — переход на отдельную review.html, а не прямо на листе внутри кабинета. Круги правок (ROUNDS) клиенту не показаны: сколько осталось. ВАЖНО. Показывать «правок осталось: N из M», открывать листы в кабинете.

ВАЖНО. Вкладка «Бриф» с возможностью дозаполнить пропущенные необязательные шаги и догрузить файлы (мост к brief.json).

### Админка

Нет входящей очереди «клиент ответил/написал»: сообщение клиента шлёт письмо админу, но в списке заказов нет столбца «непрочитанное/ждёт ответа дольше X часов» и SLA-подсветки; для 20 заказов без этого сообщения тонут. ВАЖНО. Колонка «последнее от клиента», фильтр «ждут нас», красный если >1 раб. дня.
15. Список заказов: фильтры только по статусу и поиск (номер/почта/телефон/имя); нет фильтра «ждём нас/клиента», по дате оплаты, по стилю/тарифу, нет сортировки, лимит 300, нет пагинации. ВАЖНО.
16. Карточка заказа, вкладка «Бриф»: сырой JSON в <pre> (в нём есть life/home, но человеку не читаемо), без разметки, без фото/файлов, без сводки «что важно». Новые шаги «Жизнь в квартире» и «Дом и ремонт» видны только внутри JSON. ВАЖНО. Вывести читаемую сводку (бриф.txt из intake) + список файлов с превью.
17. Передача в конвейер — полностью ручная: скачать архив -> node tools/brief-intake.js -> /new-client; в панели только подсказка. tools/brief-intake.js не разбирает life/home отдельно; статус «в работе у конвейера» в админке не меняется и не связан с clients/<slug> и выпуском. Ответы К-N выгружаются в answers.json, перенос в project.json — отдельный скрипт GOST-DRAFT. Теряется: связь заказ<->slug, прогресс конвейера, автоматическая публикация выпуска (PDF и registry.json загружаются вручную через форму, ссылка на presentation — вставляется руками). ВАЖНО -> при 10 заказах в неделю станет главным узким местом. Сделать: команда `node tools/order-pull.js LN-…` (скачивает бриф по API-токену, делает clients/<slug>, записывает slug в заказ), `tools/order-publish.js` (заливает выпуск и registry).

19. Безопасность: вход пароль + код на почту (admin_code) и белый список IP, CSRF в формах, https-only, куки Strict. Пароль в ~/.claude/secrets — единый на всё, нет ролей-операторов (adm_can есть, но роль одна), ПДн (телефон, почта) открыты целиком всем админам без маскирования и журнала просмотра карточки. МЕЛОЧЬ сейчас, ВАЖНО при втором сотруднике.
20. Дашборд: красная плашка «Условия на сайте устарели… пересоберите страницы» и «письма выключены» — полезны, но это конфиг-ошибки, а не работа; рабочая очередь («Требует действия») при пустом состоянии показывает только нули — нет списка конкретных заказов, ведущих на карточки. ВАЖНО: список должен быть «заказ -> что сделать -> с какого времени ждёт».

### Сквозное: что делает руками Александр и где встанет при 10 заказах/неделю
- Руками сегодня: проставить сумму (если null в PRICES) -> «подтвердить»; нажать «оплачен» при счёте; скачать бриф и завести clients/<slug>; запустить конвейер; собрать PDF/registry и загрузить выпуск; отвечать на сообщения и правки; внести ответы клиента в project.json; сменить статус «выдан»; разослать бригадам (запросы) — всё через админку и терминал.
