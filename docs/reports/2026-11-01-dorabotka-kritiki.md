# 01.11.2026 — доработка по критикам: защита сделки от обхода, безопасность, оплата, тексты

План — `docs/plans/2026-11-01-dorabotka-kritiki.md`. Ревью — `docs/reviews/2026-11-01-*.md` (3 критика + 2 тестировщика).
Ветка без пуша и без выкладки; боевой `config.php` и сервер не трогали.

## Решения, принятые по ходу (Александр: «на твоё усмотрение», «10 % с бригады», «оплата после первого этапа работ или аванса», «все договора через наш сайт»)
- Платы за отклик/лид нет. Удержание сделки — гарантия сайта и листы по запросу только внутри сделки.
- Ставка **10 %**; пилот — первым 5 допущенным бригадам первые 3 сделки по **5 %** (учёт по бригаде, ставка сделки хранится в `br_jobs.commission_rate`).
- Вознаграждение **начисляется** при подписании договора на сайте, **к оплате** — после первых денег бригаде: клиент отметил аванс или принял первый этап.
- Листы по запросу: в сделке без доплаты, до 15 на объект; вне сделки 2 500 ₽, но продажа выключена флагом (до ИП) — сейчас понятный отказ.
- Договор подряда и допсоглашения — **только через сайт**, подпись ПЭП кодом на почту.
- Оговорки «по такому комплекту не строят», «стоп-ошибка ждёт решения» и т. п. сняты с продающих страниц, остались одной пометкой на странице альбома (`portfolio/gost-*`). Плашка `preReview()` не тронута.
- Ссылка на черновик оферты убрана из подвала и карты сайта флагом `OFERTA_DRAFT` (site-shell.js); страница осталась (noindex).

## Что сделано
**A. Защита от обхода**
1. Единый источник условий: сервер — `BRIG_TERMS_DEFAULT` + `brig_terms()` в `server/api/lib/boot.php` (поверх — `brig_terms` в config); страницы — `BRIG_TERMS` в `tools/site-shell.js`. Цифра ставки больше нигде не зашита (brig.php, brigada.js, gen-brigady-pages.js, finance.php, katalog.php, админка, письма).
2. Контакты (телефон, почта, адрес, ИНН) открываются по `contacts_after` (по умолчанию — договор подписан обеими сторонами на сайте); до этого — лента сообщений сделки (`br_messages`). Шаблон договора до подписи — без контактов.
3. Фильтр контактов `brig_guard()`/`brig_contact_scan()`: телефоны в любых записях, почта, ссылки и домены (в т. ч. .рф), @ники, мессенджеры, «позвоните/в личку/без комиссии». Применён к предложению (комментарий, материалы, этапы), анкете (название, имя, «о бригаде»), портфолио, сообщениям, замечаниям, спорам, отзыву, «когда начать», допсоглашениям. Срабатывания — в `br_signals` без самих контактов.
4. Уникальный ИНН: миграция 2 (`inn_key` + UNIQUE; демо и тестовые не мешают); заблокированная бригада не регистрируется ни по ИНН, ни по телефону.
5. Приёмка этапа — только при всех отмеченных пунктах чек-листа (сервер + страница заказа).
6. Листы по запросу — только в активной сделке (объект «в работе»), лимит 15 на объект; воркер берёт задания только таких объектов. Платный режим вне сделки — флаг `sheets_outside_paid` (выключен).
7. Админка: вкладка «Сигналы обхода» — выбрана, но договор не подписан N дней; договор подписан, а за N дней ни аванса, ни этапа; контакты в текстах; отказы после выбора (клиентом или бригадой); повторная регистрация заблокированной; сводка по бригадам.
8. **Договор через сайт** (`server/api/lib/contract.php`): текст собирается из сделки (смета, этапы, сроки, приёмка, гарантия площадки, споры, «вознаграждение LINEA платит бригада»), версия замораживается с SHA-256, обе стороны подписывают кодом на почту (время, IP, редакция соглашения о ПЭП; SMS — флаг, выключен). Допсоглашения — так же; сумма сделки и база вознаграждения пересчитываются. Журнал сделки одинаков для заказчика, бригады и админки. Админ «за сторону» больше не подписывает.

**B. Безопасность**: `linea_ip()` — только REMOTE_ADDR (X-Real-IP — от `trusted_proxies`); чистка `rate/`; общий лимит неудачных входов в admin (`admin_fail_global`); ping без версии PHP; 0600 для правок (review.php); лимит неверного токена воркера + минимальная длина; ссылки в письмах — только от `base`/домена, не из Host; платёж на отменённый/оплаченный заказ — не «успех», пометка в истории (один раз) и письмо; смена суммы сбрасывает старую ссылку на оплату.

**C. Оплата проекта**: площадь в брифе обязательна (brief.js + brief.php), на странице заказа сразу сумма и расчёт, фраза о пересчёте — `TERMS.areaRecalc`. Чек 54-ФЗ: `yk_tax_system` из config, телефон → 7XXXXXXXXXX. Боевой режим не включали.

**D. Тексты и вёрстка**: «бесплатно» → «без комиссии / без доплаты»; воронка «5 минут» на страницах бригад (пересборка); price/ «входит» — только то, что есть в альбомах; демо-проекты прямо названы демонстрационными; сниппет каталога бригад без настоящих бригад — «Пример каталога»; Punycode в ссылке каталога; `check-domain-copy` не проверяет `api/brigade/tpl`; «скачать файл брифа»; /remont/ и /brigadam/ на 375 px без горизонтальной прокрутки (проверено в браузере: scrollWidth ≤ innerWidth), заголовок первого экрана без анимации; пример для бригад «смета 1 000 000 ₽ → 100 000 ₽» из `BRIG_TERMS`.

**Тесты**: `node tools/test-brigady.mjs` — **155 ✓ / 0 ✗** на SQLite и на MariaDB (`--mysql=`); пакет проекта — фикстура `tools/fixtures/brigady-pack.json` (на чистой машине тест зелёный). Новые проверки: контакты до/после подписи, фильтр, сигналы, ИНН, блокировка, чек-лист, листы вне сделки, отказ после выбора, подпись кодом (неверный код, без согласия ПЭП), одна версия и хеш, допсоглашение с пересчётом, пилот 5 %, «к оплате» после аванса, бриф без площади. `tools/test-units.php` (шаг 17, с макетом ЮKassa `tools/fixtures/yk-mock.php`): linea_ip, ссылки без Host, rate/, brig_terms из config, фильтр, чек, оплата отменённого заказа. `php -l` — все файлы чистые; `sync-static-nav --check`, `gen-home --check` — ок; `touch-sitemap` — 57 адресов.
