# Смета на материалы — отдельной услугой (09.11.2026)

План — `docs/plans/2026-11-09-smeta-otdelno.md`. Решение владельца: смету продаём и без дизайн-проекта LINEA; цена та же (100 ₽/м², минимум 5 000 ₽, один источник `TERMS.addons.smeta`), свой короткий бриф, оплата до работы, тот же механизм заказа.

## Что сделано
1. **Модель.** Новый вид заказа `kind = 'smeta'` (`LINEA_KINDS`, цена — `prices.smeta`, тот же ключ, что у опции; миграций не нужно: `orders.kind` — строка, SQLite и MySQL без отличий). После оплаты заказа `opt_main_sync()` создаёт основную строку `order_options` (source = order) — через неё работают загрузка PDF + таблицы, письмо, скачивание и очередь «Ждут нас»; выдача файлов переводит заказ в `delivered` (с вторым чеком 54-ФЗ, если включён). Опцию к такому заказу добавить нельзя (409). Расшифровка суммы в карточке оплаты — одной строкой («83,4 м² × 100 ₽ = 8 340 ₽»), условия — сметы (ставка, срок, точность, «чего нет»), без «кругов правок» и «визуализаций». Онлайн-оплата — тот же платёж ЮKassa (описание «Смета на материалы, заказ …»), в manual — счёт и отметка в админке.
2. **Бриф сметы.** `site/smeta/zakaz/` (подпапка, как `kabinet/`, `obmer/`: чистый адрес рядом с `/smeta/`, мета `linea-api` на два уровня выше), генератор `tools/gen-smeta-brief.js`, логика `site/js/smeta-brief.js`. Приём — `api/brief.php` с `meta.service = 'smeta'` (параметр, а не новый файл: те же https, согласие, лимиты, проверка архива, `test=1`, письма, номер LN-…, кабинет; новых эндпоинтов нет — белые списки `.htaccess` и dev-router менять не пришлось, в dev-router и `site-rebase.js` (`API_PAGES`) добавлена только мета новой страницы; `check-domain-copy.js` проверяет её). ZIP и сжатие фото продублированы из `brief.js` (≈40 строк): основной бриф не тронут.
3. **Сайт.** `/smeta/`: два входа («К дизайн-проекту LINEA» и «Отдельно: есть свой проект или только план»), блоки «что нужно прислать» и «насколько точна смета», шаги, FAQ (можно ли без проекта, что прислать, чужой проект, точность без проекта, можно ли потом заказать проект — «зачёт не обещаем»), Offer обновлён, sitemap. Упоминания «или отдельно» — `/price/`, главная, `/faq/`, `/process/`, `catalog/smeta-i-komplektatsiya.html`, галочка в брифе на проект.
4. **Кабинет и админка.** Этапы: Заявка → Оплата → Расчёт → Смета готова; вкладки «Смета / Бриф / Вопросы / История / Документы» (без правок, альбома, ремонта); свои письма (заказ получен, сумма подтверждена, счёт, оплата, смета готова) — обёртка `kab_ev()`; история и документы без слов «проект/альбом/опция». Админка: значок «только смета», фильтр «вид заказа», этапы `ADM_STAGES_SMETA`, блок «Выдача сметы», бриф «Что где отделано» словами, очередь «Посчитать и выдать смету». Ремонт по проекту для такого заказа закрыт.
5. **Тесты.** Шаг 19 в `tools/test-kabinety.mjs` (41 проверка): отказы приёма (без согласия, без плана, «есть проект» без файлов, «проекта нет» без помещений, площадь < 10), заказ без цены («уточняется»), 83,4 м² → 8 340 ₽ и 30 м² → минимум 5 000 ₽, опции не создаются, кабинет (шаги, формула, условия, список объектов), бриф словами, письма, админка, оплата → основная строка, очередь, выдача, документы, история, мост `order-pull`. Итог: **кабинеты 246 ✓ / 0 ✗** (были 205), **бригады + модули 337 ✓ / 0 ✗**. Запуск — `--port=8151`.
6. **Браузер** (локальный тестовый сервер, на боевой ничего не отправлялось): `/smeta/`, бриф сметы (шаг 1, «проекта нет», «есть проект», сводка), кабинет заказа «Расчёт» и «Смета готова» — 1280 и 375 px: горизонтальной прокрутки нет, ошибок консоли нет. Снимки — в `scratchpad/smeta2/` (`01…08-*.jpg`).

## Как устроен бриф сметы
Шаг 1 «Квартира и план»: площадь (обязательно, сумма видна сразу), план с размерами (обязательно; фото/PDF/DWG, камера на телефоне). Шаг 2 «Проект или ответы „что где“»: переключатель «У меня есть проект» (файлы листов PDF/изображения) / «Проекта нет» (по каждому типу помещений: количество, стены — краска / обои / плитка до потолка / плитка частично / панели, пол — ламинат / паркет / плитка / кварцвинил / линолеум, потолок — окраска / натяжной / гипсокартон; электрика и сантехника — да / нет / не знаю; высота потолков; состояние; «не знаю» везде). Шаг 3: сводка «так ли мы поняли» с кнопками «Изменить», контакты, согласие (редакция 27.10.2026, как у брифа на проект), сумма. У каждого вопроса — «Зачем спрашиваем». Черновик — в браузере (файлы не сохраняются, об этом сказано). Без приёмника (GitHub Pages, http) — скачать архив и отправить в WhatsApp.

## Какой набор данных получает конвейер (`order-pull.mjs <LN-…>`)
`clients/<slug>/brief.json` (`meta.service = smeta`, `smeta {mode: project | answers, rooms[], electric, plumbing, height, state, note}`), `brief.txt`, `source/plan/` — план клиента, `source/proekt/` — файлы ЕГО проекта (при `mode = project`), `order.json` (`kind: smeta`, `smetaOnly: true`, `smetaInput {mode, planFiles, projectFiles, rooms, electric, plumbing, height, state, basis}`). Основа расчёта: по проекту — его листы + план; без проекта — план + ответы «что где», допущения помечать в смете. Дизайн-проект не собирать. Результат — PDF и таблица (xlsx/csv): формат тот же, что у опции (`docs/reports/2026-11-09-opciya-smeta-materialov.md`), выдаёт админка.

## Что осталось / решения, принятые мной
- `pay_area_min.smeta = 80` (как у квартиры): сумма сметы для квартир меньше 80 м² подтверждается вручную до онлайн-оплаты. Можно поставить ниже (например, 10), если подтверждать каждую смету лишнее.
- Выдача файлов-основы для заказа-сметы идёт через строку `order_options` (source = order) — «Отмена» для неё скрыта; возврат — обычным возвратом заказа.
- Возврат/частичная выдача, отдельные формы для «чужого проекта» в разных форматах (DWG/Revit) — не делались; принимаются PDF, изображения, DWG/DXF.
- Движок расчёта сметы (другой репозиторий) не тронут: нужно научить его работать по плану + ответам «что где» и по чужому проекту (OCR/разбор листов). Пока смету готовит человек и грузит файлы в админке.
- MySQL-прогон `--mysql` не делался (SQL без специфики, схема не менялась).

## При выкладке
- В боевой `config.php` уже должна быть строка `prices.smeta` (из отчёта по опции) — отдельный заказ берёт ту же цену; без неё сумма «уточняется». В `pay_area_min` боевого config добавить `'smeta' => 80`, если там свой массив (иначе сумма всегда подтверждается вручную).
