# Отчёт: приём брифа и оплата до старта (27.10.2026)

Часть работы «доделка сайта» (`docs/plans/2026-10-27-dodelka-sajta.md`), зона «сервер»: бриф уходит в студию одной кнопкой,
у заказа есть номер и страница, проект начинается только после оплаты. **На Beget код ещё не залит** — выкладку делает
следующий шаг (`./tools/deploy-beget.sh`). На сервере уже созданы папка данных и конфиг.

## Что сделано
1. **Приёмник на PHP** — `server/api/` (не в `site/`: GitHub Pages опубликовал бы исходники). При выкладке на Beget
   `tools/site-rebase.js` кладёт его в `api/` и вставляет `<meta name="linea-api" content="api/">` в brief.html, review.html
   и order.html. На GitHub Pages меты нет, и сайт работает по-старому.
   - `brief.php` принимает multipart (ZIP-архив брифа и отдельно brief.json). Ограничения: архив до 100 МБ; внутри только фото,
     PDF, DWG/DXF, json и txt; до 300 файлов; без путей вида `../`; архив не распаковывается. Защита от спама: поле-ловушка
     и не больше 5 принятых брифов в час с одного адреса. Номер заказа — `LN-ГГММ-NNNN`, токен — 32 hex-символа. Архив
     хранится в `linea-private/orders/<номер>/brief.zip`, заказ — строкой в `linea.sqlite`: согласие на обработку данных
     (дата и текст), IP, сумма, данные платежа, флаг test.
   - `order.php?t=` отдаёт состояние заказа без телефона, почты и адреса. Если по заказу висит платёж, сначала сверяется с ЮKassa.
   - `pay.php` и `pay-notify.php` работают с ЮKassa API v3 (перенос из konsulcar с доработками под заказы LINEA):
     - запросы с Basic-авторизацией `shopId:secretKey`;
     - Idempotence-Key = номер заказа + номер попытки, а живой pending-платёж моложе часа используется повторно — двойного платежа нет;
     - сумма берётся только из заказа;
     - вебхук берёт из тела запроса только id и проверяет его через `GET /v3/payments/{id}`. Заказ отмечается оплаченным
       один раз и только если совпали сумма и `metadata.order`.
     Включается так: `mode = 'yookassa'` плюс ключи магазина. Пока ключей нет, режим принудительно `manual`.
   - `admin.php` — закрытая страница заказов. Вход по паролю (bcrypt), сессия HttpOnly + SameSite=Strict, CSRF на каждое
     действие, после 5 неудачных входов пауза 15 минут. Что умеет:
     - список заказов с фильтром по статусу и карточка заказа (бриф и история);
     - скачать архив брифа (отдаётся из linea-private);
     - выставить сумму и вид услуги;
     - отметки «счёт выставлен», «оплачен» (кто и когда), «выдан» со ссылкой на альбом, «отменить»;
     - «удалить тестовый»;
     - отдельный список правок к листам.
   - `review.php` принимает правки к листам (JSON до 1 МБ) и сохраняет их в `linea-private/reviews/<слаг>/`. Если в ссылке
     есть токен заказа (`&t=`), правки привязываются к заказу.
   - `prices.php` отдаёт публичные цены из того же конфига; `ping.php` нужен для прозвона.
   - `lib/notify.php` — письмо Александру через `mail()`. **По умолчанию выключено** (`notify_enabled = false`, письма только
     пишутся в журнал `mail.log`). Тестовые заказы писем не шлют никогда.
   - `.htaccess` в `api/` пропускает только перечисленные `*.php`, `api/lib/` закрыт. Данных в веб-корне нет вообще.
2. **brief.js**. На Beget кнопка называется «Отправить бриф в студию»: архив уходит через XHR, видна полоса процентов, при
   обрыве связи один автоматический повтор. После ответа сервера открывается `order.html?t=…`, черновик очищается. Ошибки,
   которые клиент может исправить сам (телефон, размер, лимит), показываются текстом. Если сервер упал или не ответил,
   сайт откатывается к прежнему способу и отдаёт готовый архив для WhatsApp или почты. Флаг `meta.test` теперь ставится
   **только при `?test=1`** (раньше он был зашит в каждый бриф). Архив больше 100 МБ не отправляется, клиент видит понятное
   сообщение. Про HEIC предупреждаем.
3. **order.html + js/order.js** (собирается `tools/gen-order-page.js` на общем каркасе, noindex). На странице этапы
   «Бриф получен → Оплата → В работе → Альбом выдан». Текст всегда говорит, что **проект начнётся после оплаты**. Если сумма
   ещё не назначена — «назовём цену в течение рабочего дня». В ручном режиме — «счёт пришлём / счёт выставлен». В режиме
   yookassa — кнопка «Оплатить N ₽». После оплаты показан срок 48 или 72 часа от момента оплаты и честная оговорка про
   «ПРЕДВАРИТЕЛЬНО», пока по объекту открыты вопросы (это замечание практика Андрея).
4. **review.js**. На Beget правки уходят на сервер, клиент видит «Правки приняты, № R-…». Добавлено поле «Телефон».
   Токен заказа и `test` теперь сохраняются в адресе при листании листов (раньше слетали). WhatsApp и почта остались запасным путём.
5. **site-rebase.js и deploy-beget.sh**. Служебные файлы выпусков (`_release.html`, `_rules.txt`, `_card.json`,
   `_renders.json`) больше не выкладываются. `.htaccess` закрывает `.linea-deploy` и их же, у `.json` задан срок кэша 1 час.
   Прозвон проверяет `api/ping.php` (PHP, папка данных, конфиг), а также что `api/lib/boot.php` и `api/.htaccess` закрыты.
6. **Beget** (одно SSH-соединение, пароль нигде не печатался):
   - создана папка `~/dizain-studiya-kvartir/linea-private/` (права 0700) с подпапками `orders`, `rate`, `sessions`, `reviews`;
   - создан `config.php` (права 0600): `mode = manual`, ключи ЮKassa пустые, все цены `null` («уточняется»), уведомления
     выключены, `admin_hash` — bcrypt-хэш нового пароля;
   - все PHP-файлы прошли проверку синтаксиса на PHP 8.2 сервера, SQLite и ZipArchive работают;
   - `open_basedir` не задан, `upload_max_filesize` и `post_max_size` ≈ 999 МБ.

## Проверка (локально: php -S на копии `.deploy/preview` + встроенный браузер)
- **Бриф с `?test=1`.** Мастер пройден, кнопка «Отправить бриф в студию» нажата, открылась страница заказа: «Заказ №
  LN-2610-0010, тест · ждёт оплаты · 45 000 ₽ · Оплатить». Это режим yookassa на макете API ЮKassa.
- **Отказы приёмника:**
  - без контактов → «Оставьте телефон или e-mail»;
  - `.php` в архиве → отказ;
  - не ZIP → отказ;
  - поле-ловушка → ответ «ок», но ничего не сохранено;
  - 6-й бриф за час → 429;
  - GET → 405;
  - `api/lib/boot.php` → 404.
- **Оплата на макете API** (локальный макет, настоящая ЮKassa не вызывалась):
  - повторное нажатие «Оплатить» вернуло тот же платёж;
  - выдуманный id в вебхуке → 200 без изменений;
  - **поддельное тело «succeeded» с id настоящего неоплаченного платежа → 200, заказ остался «ждёт оплаты»**;
  - после настоящего succeeded возврат на `order.html?pay=back` → «Оплачен — проект в работе», срок до 29 октября;
  - повторный вебхук второго события не дал;
  - canceled → платёж сброшен, следующая попытка — новый платёж с новым ключом;
  - сумма не совпала → заказ не оплачен, в истории запись «проверить вручную».
- **Ручной режим.** Без суммы: «назовём цену… работу начинаем после оплаты». В admin.php:
  - вход, неверный пароль, устаревший CSRF → отказ;
  - «оплачен» без суммы → «сначала выставьте сумму»;
  - после суммы 45 000 → paid с отметкой «вручную: <кто> <дата>», это видно и в order.php;
  - архив скачивается.
- **Правки** `review.html?p=gost-kv3k&test=1` → «Правки приняты, № R-261027-…».
- **Как на GitHub Pages** (site/ без меты): кнопка «Отправить бриф с файлами», прежние тексты, `meta.test` отсутствует.
  Запасной путь на Beget (имитация ошибки 404 у приёмника): сообщение «Через сайт отправить не получилось», архив готов
  для WhatsApp.
- Все тестовые заказы, правки и база были локальными, в scratchpad, и удалены. **На Beget тестовых заказов не создавалось,
  писем не отправлялось.**

## Что осталось
1. **Выкладка** `./tools/deploy-beget.sh` (следующий шаг). После неё проверить:
   - `api/ping.php` → `"private":true,"config":true` (если false — веб-PHP не видит папку данных);
   - сквозной тест с `?test=1` на техническом адресе и удаление тестового заказа кнопкой в admin.php.
2. **Противоречие в текстах.** Плашка сайта (`SHELL.beta`) и подзаголовок brief.html говорят «Открытый тест: дизайн-проект
   бесплатно, без предоплаты», а приём теперь ведёт к «проект начнётся после оплаты». Нужно решение Александра и правка
   текстов (зона текстов, `tools/site-shell.js` и brief.html). Страница `thanks/` («Бриф отправлен») осталась только для
   запасного пути.
3. **Альбомы клиентов по неугадываемому адресу.** Нужна папка `/c/<токен>/` вместо публичной `portfolio/<слаг>/`, review.js
   должен уметь её грузить, а REVIEW_BASE и `meta.siteSlug` в gost-draft `engine/work.js` — перейти на эту схему. Не сделано:
   это задача движка gost-draft и выкладки альбомов.
4. **Вебхук ЮKassa** работает только по HTTPS, то есть после домена и SSL. До этого оплату подтверждает перепроверка в
   `order.php` при возврате клиента с оплаты.
5. При домене сайту нужен PHP 8.2+: версия задаётся у домена в панели Beget, сейчас 8.2 стоит только у техадреса.
6. Мелочи из замечаний не сделаны: `favicon.ico` (сейчас 404) и мягкая 404 на прямой `/404.html`.
