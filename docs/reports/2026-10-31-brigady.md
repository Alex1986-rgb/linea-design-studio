# Отчёт: сервис «Ремонт по проекту» — бригады, подбор, этапы, комиссия (31.10.2026)

Ветка `brigady` (worktree `~/projects/linea-brigady`, sparse-checkout без `site/portfolio/` — на диске было свободно ~300 МБ).
План — `docs/plans/2026-10-31-brigady.md`. **Ничего не выложено на Beget, не запушено, писем наружу не уходило.**

## Что сделано
1. **База и аккаунты.** Весь новый код ходит в базу через тонкий слой `server/api/lib/db.php` (PDO: `db_one/all/val/exec/insert/update/tx`).
   Схема — только `lib/migrations.php` (версия 1; таблица `schema_version`), типы меткой `{ID} {KEY} {SHORT} {EMAIL} {TEXT} {INT} {REAL} {BOOL}`
   переводятся под SQLite или MySQL 5.7 (utf8mb4/utf8mb4_unicode_ci, InnoDB, индексы ≤ 767 байт, без JSON-функций, CHECK, DEFAULT у TEXT;
   колонка `stored` переименована в `stored_path` — в MySQL 5.7 это зарезервированное слово). config `'db' => ['dsn','user','pass']` → MySQL
   для ВСЕГО (и заказы `orders/events`, и сервис бригад: `linea_db()` в boot.php отдаёт то же соединение и запускает миграции); нет `'db'` — SQLite.
   `brief.php` больше не завязан на `BEGIN IMMEDIATE` (на MySQL — транзакция + `FOR UPDATE`). Общий модуль `lib/accounts.php` (роль `brigade`;
   `client`/`admin` — при переезде): password_hash, сессия `linea_acc` (httponly, secure на https, SameSite=Strict), CSRF, блок на 15 мин после
   5 ошибок, восстановление одноразовой ссылкой на 1 час (в базе только sha256 токена).
2. **Перенос SQLite → MySQL** — `server/tools/migrate-sqlite-to-mysql.php --private=<linea-private> [--apply]`: сухой прогон по умолчанию, те же id,
   отказ при непустой цели, сверка количеств. Проверен на локальной MariaDB 12 (19 таблиц, все количества сошлись; повторный запуск отказывает).
3. **Кабинет бригады** `/brigada/` (`site/js/brigada.js` ← `api/brigade/*.php`): регистрация (форма, ИНН с проверкой контрольной суммы, специализации,
   районы МСК/МО, состав, опыт, гарантия, рекомендатели, согласия ПДн + правила + агентский договор с редакциями), вход, выход, восстановление;
   портфолио «до/после» (≥ 3 объекта для отправки), логотип; статусы draft → review → active → suspended/blocked; лента обезличенных запросов
   (только допущенным); предложение по позициям сметы (цена за единицу или «не делаем», материалы, график этапов, старт, гарантия, комментарий;
   правка до срока; сумма считается на сервере); объекты (контакты и адрес клиента — только после выбора и согласия клиента), «договор подписан»,
   фото этапа, «готов к приёмке», закрытие замечаний, споры; «Нужен лист» (текст, диктовка Web Speech, запись голоса); финансы (7 %, счета, оплата,
   рейтинг и отзывы). На телефоне форма предложения — карточками.
4. **Клиент** — блок «Ремонт по проекту» на `order.html` (`site/js/remont.js` ← `api/remont.php?t=`): «Подобрать бригаду» с согласием на
   передачу обезличенного проекта, приглашение бригады из каталога (токен — через sessionStorage, не в адресе), сравнение 2–5 предложений
   в одной таблице по позициям (итого, срок, гарантия, материалы, рейтинг, проверка, фото объектов, лучшая цена по строке), выбор с согласием
   на передачу контактов, договор подряда `api/remont-dogovor.php` (HTML → печать в PDF; приложения: проект, смета по позициям бригады,
   график, порядок приёмки с чек-листами), «договор подписан», приёмка этапов по чек-листу / возврат с замечаниями, отзыв (только после
   завершения, один раз), споры. Проект без бригады — нормальный путь.
5. **Чек-листы приёмки** — из правил технадзора GOST-DRAFT (`specialists/quality-inspector/rules.json`: СП 71 п. 4.6 и табл. 7.4/7.6/8.5/8.15,
   СП 73, ПУЭ гл. 1.8, ГОСТ IEC 61008-1), 11 видов этапов; ключ выбирается по названию этапа.
6. **Админка** `api/admin-brigady.php` (тот же пароль и сессия, что admin.php; ссылка «Ремонт и бригады»): бригады (анкета, фото, ИНН —
   контрольная сумма, ссылки ФНС НПД/ЕГРЮЛ/Прозрачный бизнес/Федресурс, кнопка **открытого API ФНС статуса НПД** `statusnpd.nalog.ru` без
   ключа; отметки «ИНН проверен»/«видеозвонок»; допуск только после обеих; приостановка/блок с причиной), запросы (загрузка пакета
   pack.json + xlsx/PDF, автоподбор по району/специализациям/рейтингу, ручная правка, срок, рассылка/досылка), все предложения, объекты
   и этапы (отметка подписания за сторону с основанием), споры (переписка, решение), комиссия (счёт LB-ГГММ-NNNN, оплата, CSV), отзывы
   (скрыть только по 5 причинам правил, с пояснением; вернуть), очередь листов, журнал (все / только админ).
7. **Каталог** `/brigady/` и `/brigady/<slug>/` — рендер из базы (`api/katalog.php`, rewrite в `.htaccess` из site-rebase.js), вид по макетам
   `docs/brigady/primer-*.html` в токенах сайта: фото 1 + 2, чипы, 3–4 показателя, «Официальные данные», «Карточка / Пригласить», «Вы бригада?».
   Фильтры: работы, район, рейтинг, бюджет. Только допущенные; телефон и почта не публикуются; имя бригадира — по согласию; значки «ИНН
   проверен (дата)», статус, «видеозвонок», «договор подряда», «по проектам LINEA: N», рейтинг/отзывы — только реальные; schema.org
   HomeAndConstructionBusiness, AggregateRating — только при реальных отзывах; `/brigady/sitemap.xml` (строка Sitemap в robots — site-rebase).
8. **Демо** — `server/tools/seed-demo.php [--purge]`: 3 «Бригада-пример: …» по макету, фото — визуализации prompt-kv54 (`site/assets/brigady-demo/`,
   1200/640 px) с подписью «иллюстрация из проекта LINEA»; без ИНН, проверок, рейтинга, отзывов, времени ответа и цен; плашка «Пример карточки»,
   noindex, без schema.org, вне sitemap, подбора, приглашений; вход в демо-аккаунты закрыт. Каталог показывает их, только пока нет настоящих.
9. **«Лист по запросу»** — очередь `br_sheet_reqs` + зеркало `linea-private/sheet-requests/<id>.json`, API воркера `api/sheets-worker.php`
   (токен из config, только https, без ПДн клиента), статусы в кабинете, письмо бригаде, история, лимиты. Протокол — `docs/brigady/sheet-request-api.md`.
10. **Уведомления** — `lib/brig-notify.php`: 15 шаблонов, mail(); `brig_mail_enabled=false` по умолчанию; test=1 и `LINEA_MAIL_DRY` — никогда;
    журнал без адресов, ссылок и токенов. Telegram — заготовка (`tg_enabled=false`).
11. **Страницы** (`node tools/gen-brigady-pages.js`, каркас site-shell): `/remont/` (схема «проект → выбор → этапы с листами → приёмка», пример
    сравнения на условных ценах с пометкой, пример листа по запросу из `gost-draft-sheetreq`, кто за что отвечает), `/brigadam/` (условия, 7 %,
    проверка, как получать заказы, регистрация), черновики noindex «редакция от 31.10.2026, проект»: `/brigadam/pravila/`, `/brigadam/dogovor/`,
    `/remont/usloviya/`. Тексты поправлены по `docs/reviews/2026-10-31-kritik-yurist.md`: агент действует от имени бригады; LINEA — не исполнитель
    и не технадзор; реквизиты бригады клиенту до выбора; рейтинг и ранжирование, обжалование блокировки, отказ заказчика до начала работ,
    регресс, согласие на публикацию. В `site-shell.js` одна правка: разделы «Ремонт по проекту» и «Бригадам» в SECTIONS (`menu: false` — подвал).
12. **Безопасность**: доступ к каждому объекту по владельцу; CSRF на всех POST (сессия — X-CSRF; клиент — HMAC от токена заказа); лимиты
    (регистрация, вход, восстановление, загрузки, действия клиента, воркер); загрузки — JPEG/PNG/WebP (пережатие GD ≤ 1600 px, EXIF и геометки
    стираются), PDF по сигнатуре, xlsx (админ), аудио; имена случайные; хранение вне веб-корня; отдача через PHP с проверкой прав и `nosniff`
    + CSP sandbox; SQL только подготовленные; вывод экранируется; https-only как у брифа; сбой — JSON без подробностей, детали в error.log.
    В белый список `api/.htaccess` добавлен и `survey.php` (его там не было — форма обмера на Beget получала бы 403).

## Роли и права
| Кто | Видит | Может |
|---|---|---|
| Гость | каталог (только допущенные; телефон не виден), страницы | зарегистрировать бригаду |
| Бригада «на проверке» | свою анкету | править анкету и портфолио; **запросы не видит (403)** |
| Допущенная бригада | разосланные ей запросы без ПДн клиента; свои предложения/объекты | предложение до срока; после выбора — контакты клиента, этапы, листы, споры |
| Клиент (токен заказа) | свой запрос, предложения (без контактов бригад до выбора), свой объект | подбор, приглашение, выбор, приёмка, отзыв, спор |
| Администратор (admin.php) | всё | проверка и допуск, рассылка, счета, модерация отзывов (по правилам), споры |
| Воркер листов (токен) | задания без ПДн | вернуть PDF / вопрос / отказ |

## Не сделано / ограничения
- MySQL **5.7** вживую не проверял — только MariaDB 12 (синтаксис миграций сведён к общему подмножеству 5.7; колима с mysql:5.7 не поднимал:
  на диске ~2 ГБ). Перед переключением боевого — прогнать `migrate-sqlite-to-mysql.php` без `--apply` на сервере.
- **Порядок выкладки важен**: с `'db'` в боевом config.php после заливки этого кода заказы начнут писаться в MySQL. Значит: заливка →
  сразу `php server/tools/migrate-sqlite-to-mysql.php --private=… ` (сухой) → `--apply` → проверка admin.php. Либо временно убрать `'db'` до переноса.
- Места, завязанные на SQLite: только ветка `linea_db()` без `'db'` в `boot.php` (PRAGMA) и `brief.php` (BEGIN IMMEDIATE — только для SQLite-ветки),
  `migrate-sqlite-to-mysql.php` (читает SQLite by design). Новый код SQLite-специфики не содержит.
- «Безопасная сделка» ЮKassa — не включалась (оплата ремонта вне сайта; в «Финансах» флаг `safeDeal:false`); по юристу — только после юриста.
- Ведомости xlsx в пакете: `brigady-pack.mjs` их собирает через exceljs из GOST-DRAFT, но на маке exceljs не установлен — собрать на SmartApe
  (или `npm i` в gost-draft) и загрузить в запрос; в тесте — заглушка xlsx.
- Подвал новых разделов появится на остальных страницах при их следующей пересборке (по просьбе координатора главную и разделы не трогал);
  `site/brigady/index.html` — заглушка для GitHub Pages (там нет PHP).
- Кабинет и каталог — в тёмной теме сайта (в задаче «светлая», но «как у сайта»: сайт LINEA тёмный, main.css).
- 640-px версии демо-картинок лежат в `site/assets/brigady-demo/`, каталог пока отдаёт 1200 px через file.php.
