### Сервер
- **В1. Расторжение.** Вознаграждение считает `brig_termination_fee()`:
  - база `accepted` — принятое по акту, но не ниже оплаченного по реестру;
  - база `paid` (теперь реализована) — всё, что подрядчик получил (включая отметки «получено» самой бригадой), но не ниже принятого по акту.

  Два случая требуют подтверждения LINEA (`needs_admin`), без него соглашение не подписывается:
  - вознаграждение по акту ниже выставленного счёта;
  - акт на 0 после открытых контактов — этот случай ещё и даёт сигнал обхода `termination_zero`.

  Подтвердить или отклонить — в `admin-brigady.php?j=…`. Если счёт выставлен уже после предложения, а подтверждения нет, вознаграждение остаётся на сумме счёта.
- **В2. Второй чек.** Миграция 8 добавила `orders.payment_receipt` (платёж создан с чеком) и `paid_receipt` (ставится при оплате; признаком служит и `receipt_registration` в ответе ЮKassa). В config появился ключ `yk_receipts_since`.
  - Второй чек, cron и возврат через API работают только при `yk_receipt_chain()`.
  - По старым заказам в заказ пишется событие «выбить вручную», возврат идёт ручным путём.
- **С1.** Пока есть неподписанное соглашение о расторжении, приёмка этапа даёт 409. Устаревший акт не подписывается. Если принятое больше цены договора после допсоглашения, акт составляется по принятому с понятным текстом отказа для работ сверх него.
- **С2. Возвраты.**
  - `yk_refund_reconcile()` работает в cron (шаг 9) и перед каждым новым возвратом. Висящие возвраты сверяются через `GET /refunds/{id}`, потерянные — через `GET /refunds?payment_id`.
  - Вебхук, пришедший раньше записи id, привязывается к нашей операции по платежу и сумме.
  - После сбоя без ответа возврат другой суммы отклоняется, а повтор той же суммы безопасен (тот же ключ идемпотентности).
  - Явный отказ кассы (4xx) помечается как `rejected` и сумму не держит.
- **С3.** Статус «Возврат оплаты» больше не ставится сменой статуса, только через «Возврат». Ручной возврат записывается одним UPDATE с условием, повторное нажатие за 2 минуты отклоняется.
- **С4 и низкий пункт про чек.**
  - Пока возврат в пути, второй чек не уходит.
  - cron повторяет второй чек не чаще раза в час. Через сутки повторы прекращаются (ключ ЮKassa живёт 24 часа), и в заказ пишется пометка «вручную».
  - Обезличенные заказы второй чек не получают.
- **С5. Автоудаление ПДн.** Сделку не трогает, пока по ней есть открытое разногласие, неоплаченный счёт, вознаграждение к оплате без оплаченного счёта или неподтверждённые записи реестра. Причина пишется в `pd.log`, заказ ждёт вместе со сделкой. Заказ с неушедшим вторым чеком тоже ждёт. Минимум `retention_years` поднят до 3.
- **С6. Вход в админку.**
  - Результат отправки письма с кодом теперь проверяется. Если письмо не ушло ни на один адрес, страница прямо говорит об этом и показывает аварийный путь: аварийный адрес, доверенное устройство, `admin_2fa=false` + `otkat-config.sh`. Там же кнопка повторной отправки, запись в журнал и Telegram.
  - Доверенные устройства привязаны к паролю: смена `admin_hash` их гасит. В настройках у каждого устройства своя кнопка «Отозвать».
- **С7. `ping.php`.** Токен принимается только из заголовка. Лимит частоты применяется только к неверным попыткам и после сверки, поэтому чужие ошибки не запирают монитор.
