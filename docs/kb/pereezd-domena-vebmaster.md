## Главное, что надо знать заранее

1. **Старый сайт — папка на github.io, а не домен.** Отсюда:
   - Яндекс склеивает в зеркала только домены целиком, инструмент «Переезд сайта» для папки недоступен;
     межхостовый `rel=canonical` Яндекс не учитывает. Для Яндекса работает только переход со старой страницы:
     мгновенный `<meta http-equiv="refresh">` он обрабатывает как редирект (как 302).
     Справка: yandex.ru/support/webmaster → «Переезд сайта на новое доменное имя» («используйте метатег, если другие
     способы перенаправления не подходят»).
   - В Google Search Console «Изменение адреса» тоже не подходит: инструмент работает от корня домена с 301, а не от папки.
     Google считает мгновенный meta refresh постоянной переадресацией и учитывает межсайтовый canonical.
   - Вывод: Яндекс проиндексирует домен как **новый сайт**, накопленное старым адресом почти не перейдёт. Сайту мало
     времени, потери небольшие — главное, чтобы старые адреса не висели в выдаче дублями.
2. **Поэтому страницы-переходы на GitHub Pages ставить сразу**, в день переезда, а не через 1–3 месяца (как было в
   отчёте `2026-10-27-pereezd-beget.md`): пока Pages отдаёт полный сайт с canonical на домен, для Яндекса это дубль.
   Решение за Александром; по умолчанию — переходы сразу после push.
3. **Pages не выключать, пока живы выданные PDF.** Ссылки «Правка к этому листу» в альбомах ведут на
   `…github.io/linea-design-studio/review.html?p=…&s=…`. Страница-переход переносит `?p=…&s=…` на домен (скрипт
   `location.replace` с `location.search`). Выключать Pages можно, только когда все выданные альбомы перевыпущены
   с новым адресом (gost-draft: `engine/work.js` → `REVIEW_BASE`, или `meta.reviewBase` в project.json).

## GitHub Pages: страницы-переходы

Собирает `node tools/gen-pages-redirect.js` → `.deploy/pages-redirect/` (сам ничего не применяет; `switch-to-domain.sh`
собирает и проверяет их на каждом прогоне):
- на каждую HTML-страницу `site/` — страница с тем же именем: `location.replace` (сохраняет `?query` и `#якорь`),
  `<meta http-equiv="refresh" content="0; url=…">` и `<link rel="canonical">` на **тот же путь** на домене;
  `…/index.html` → `…/`; служебное, которого на домене нет (`_release.html`, `_dev-*.html`), → папка;
- `404.html` — переход для всего остального (PDF, листы SVG, картинки, удалённые страницы) на тот же путь домена;
- `.nojekyll`, `redirects.tsv` — таблица «старый → новый» (её сверяет `tools/check-domain-copy.js --redirects=…`).

Как применить (после push переключения, домен открыт по https) — один из вариантов, решает Александр:
- **А (рекомендую):** в `.github/workflows/pages.yml` перед `upload-pages-artifact` добавить шаг
  `- run: node tools/gen-pages-redirect.js --out=_pages-redirect` и поменять `path: site` на `path: _pages-redirect`.
  Pages собирает переходы сам из текущей `site/`, в git ничего лишнего. Откат — вернуть `path: site`.
- Б: закоммитить содержимое `.deploy/pages-redirect/` в отдельную ветку и публиковать Pages из неё.

Проверка после выкладки Pages (через 1–3 минуты):
- [ ] `curl -s https://alex1986-rgb.github.io/linea-design-studio/catalog/ | grep -E 'refresh|canonical'` — обе строки на домен;
- [ ] в браузере старый адрес главной, статьи журнала, `review.html?p=gost-kv3k&s=…` — открывается тот же путь на домене
      с теми же параметрами; PDF и лист SVG по старому адресу — уводит на домен.
