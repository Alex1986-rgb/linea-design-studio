# Практик-человек в конвейере (/qa GOST-DRAFT) — предложение

> Только описание. Код GOST-DRAFT (`~/projects/gost-draft`, рабочее дерево `gost-draft-svod`) в этой работе не менялся.
> Правки движка ниже — задачи для отдельного круга, владельцы указаны.

## Где сейчас стоит «практик»

`/qa <слаг>` (`.claude/workflows/project-qa.js`): сборка → **критики параллельно** (практик, нормоконтроль, скептик, приёмщик)
→ исправления по владельцам → пересборка, до 3 кругов. «Практик» там — **ИИ-агент в роли Андрея** («Ты — Андрей, практикующий
проектировщик…»). Это полезная имитация, но не человек: его вердикт нельзя выдавать за проверку специалистом, и ставить по нему
подпись «Пров.» нельзя.

## Как встроить человека

```
сборка → ИИ-критики (до 3 кругов) → ИИ-итог «можно отдавать?» → [НОВОЕ] практик-человек → исправления → повтор у практика → выдача
```

1. **Вход** — только после ИИ-кругов: 0 блокеров у ИИ-критиков, отчёт `/qa` есть. Человеку не отдаём то, что машина уже нашла
   (дорогие часы на дешёвые замечания).
2. **Передача** — Александр отправляет PDF студии + полный + сопроводительную записку «что известно и открыто» (реестр К-N,
   итог /qa) и чек-лист `docs/praktik/cheklist.md`.
3. **Ответ** — форма `forma-otveta.csv` → кладём как есть в `docs/reviews/ГГГГ-ММ-ДД-praktik-<слаг>.md` (текст практика не правим;
   наша разметка — отдельной колонкой «владелец / пункт rules.json»).
4. **Раздача** — каждое замечание получает владельца по `knowledge/team.md`; закрытие — по `knowledge/zakrytie-zamechanii.md`
   (причина, не подгонка; факт объекта — вопрос в реестр, а не выдумка). Повторяющееся замечание — новое правило в `rules.json`
   владельца с источником «практик, дата» и негативным тестом (`node specialists/normcontrol/selftest.mjs`) — так человек
   учит машину, и следующий альбом это уже не пропустит.
5. **Повтор** — практик смотрит только свои замечания по исправленному выпуску; закрывает их **он**, не мы.
6. **Подпись** — см. ниже. Без неё альбом выдаётся с пустой графой «Пров.» — честно.

## Подпись «Пров.» — без подписей за него

Правило проекта уже есть: подпись, обмер и подтверждение — **факты, которые приносит человек**; агент записывает их только со
ссылкой на сообщение (дата, суть), скептик проверяет (`knowledge/zakrytie-zamechanii.md`, раздел «Как записывать решение…»;
правила SH-49…SH-55). Для практика то же:

- `meta.checker` (графа «Пров.», ГОСТ Р 21.101, гр. 12; сейчас SH-25 — warn) заполняется **только** когда практик письменно
  написал «проверил выпуск №… от ДД.ММ.ГГГГ, замечаний категории А нет» (или подписал PDF/скан).
- Рядом в данных — событие: `meta.checkedBy` + `meta.checkedOn` + номер выпуска и ссылка на сообщение (в отчёте круга).
  Новый выпуск после правок ≠ проверенный: подпись относится к конкретному выпуску; пересборка с изменением листов — графа
  снова пустая до его повторного «проверил».
- В отчёте /qa — две разные строки: «ИИ-критики: …» и «Проверил человек: ФИО / не проверялось». ИИ-практика переименовать
  в «ИИ-практик», чтобы его вердикт не читался как живой.
- Сайт LINEA: формулировка «проверяют специалисты» допустима только для альбомов, где графа «Пров.» реально заполнена;
  до этого — как сейчас на price/: «Подписей проверяющего и нормоконтролёра на листах нет: в штампе — автор».

## Что практик не делает

- Не подписывает за автора, ГИПа и нормоконтроль; не отвечает за обмер и несущие (это техзаключение и обмер — факты объекта).
- Не правит файлы проекта — только замечания.
- Его имя не появляется на сайте без его письменного согласия.
