# LINEA 2.0: одна модель → чертежи, рендеры, IFC и реальные товары магазинов

Итог 28.10.2026 после 4 исследований (открытые движки, магазины и партнёрки РФ, 3D-модели товаров, требования практиков
и конкуренты) и 2 критиков (технический — по коду gost-draft; бизнес/юрист). Чертёжная часть ведётся в
`~/projects/gost-draft` (решение 21.09.2026), сайт и заказы — в этом репозитории.

## 0. Главное в трёх строках

1. **Ничего не клонируем целиком.** Проприетарное (Revit, ArchiCAD, Planner 5D, Remplanner) нельзя по лицензиям и незачем;
   открытое берём библиотеками: IfcOpenShell (LGPL) для IFC, Blender (GPL, только на сервере) для рендера.
2. **`project.json` остаётся источником истины.** Из него один общий модуль сцены выдаёт всё: листы, рендер, IFC, спецификацию.
   Так «рендер = план» достигается общим источником, а не переписыванием движка.
3. **Магазины — добавка, а не основа дохода.** Честный расчёт: 10–25 тыс. ₽ комиссий с проекта. Основа — оплачиваемый проект
   и комплектация как услуга (7–12 %). Подключать партнёрки после первых 3–5 платных клиентов.

## 1. Зачем

Практик (Revit) нашёл, что альбом «непригоден для прораба»: рендер не совпадает с планом (остров «мигрирует»), проём путается
с полотном, развёртки — хаос. Технический разбор: геометрия у рендера и листов уже общая (`tools/render-clay.js` строит «глину»
из того же `project.json`), а **расхождение даёт ИИ-перерисовка** (`tools/imgen.js`, img2img по глине) — она дорисовывает
и сдвигает предметы, а сверка `views-check.js` заполняется глазами.

Зазор на рынке: Remplanner — чертежи без реальных товаров; Лемана/INMYROOM — товары без чертежей; Planner 5D/HomeByMe —
без ГОСТ и с проблемами оплаты из РФ. Устойчивое преимущество LINEA — **ГОСТ-оформление + автоматическая сверка
лист ↔ модель ↔ рендер ↔ товар + подтверждение практика**. «Спецификация со ссылками» сама по себе копируется за месяц.

## 2. Архитектура (исправлена после критики)

```
project.json (истина: допущения, why/refs, реестр, ~100 правил, самотесты)
      │
      ▼
engine/scene.js  — НОВЫЙ общий модуль: список объектов с GUID (хеш id+помещение), рёбра стен
      │             (дедупликация общих стен, контур из outline), поворот, габарит, проём/полотно
      ├──► листы ГОСТ (как сейчас, без изменений — байт-сверки выпуска не ломаются)
      ├──► render-clay.js (глина) + маски объектов и карта глубины
      │        └──► ИИ-перерисовка С ПРИВЯЗКОЙ по маскам/глубине + АВТОсверка кадра с frameContents()
      ├──► model.ifc (IfcOpenShell на сервере) → подрядчику в Revit/ArchiCAD
      ├──► серый рендер Blender (контроль геометрии; фотореализм — если сервер потянет)
      └──► спецификация: позиция ↔ товар (артикул, габарит ИЗДЕЛИЯ, ссылка, цена, источник габарита)
```

**Отклонено критиком и вычеркнуто:** «GOST-DRAFT берёт геометрию из IFC» (сломает 26 специалистов, ~100 правил, самотесты
и байт-сверки, потеряет реестр допущений) и веб-редактор на старте.

Чего не хватает в `project.json` (добавить в схему):
- поворот предмета производной `rotation` (сейчас ориентация стеной и `faces`);
- `leaf` (полотно) обязательным у всех дверей; правило «проём ≈ полотно + 100, точно — по каталогу системы»;
- единая ±0,000 по проекту (сейчас «от чистого пола своего помещения»);
- у предмета: `sku`, `url`, `price`, `dimsSource` (изделие/упаковка/шаблон), `licenseOfModel`;
- точки подключения сантехники/техники — из паспорта выбранной модели, иначе пометка «ПРЕДВАРИТЕЛЬНО».

## 3. Рендер на сервере — сначала проверить железо

SmartApe: 2× Xeon E5-2660 (Sandy Bridge, **без AVX2**), 32 потока, без GPU, Windows Server 2022. MongoDB 8 на нём уже не
запустилась из-за AVX2 — тот же риск у Blender 4.x и шумоподавителя OIDN. **Блокер этапа рендера: проверить, какие сборки
Blender запускаются** (3.6 LTS / 4.x, с OIDN и без). Оценка Cycles на CPU: 10–40 мин на кадр 2000 px → 5–15 ч на проект;
годится для выпуска, не для итераций. Сервер уже делит потоки со сборками альбомов и Alpine — нужен лимит потоков и очередь.
EEVEE без GPU на Windows Server ненадёжен. Отсюда: **Blender — серый контрольный рендер, фотореализм — ИИ с жёсткой привязкой
к маскам и глубине из сцены**, брак отсекается автосверкой.

## 4. Товары: откуда модели и данные

Лестница качества у каждого предмета (поле `dimsSource`):
1. **Модель производителя** (RFA/IFC/GLB) с записанной лицензией. Первыми — сантехника и инженерка с BIM-библиотеками
   и техлистами (Geberit, Hansgrohe, Roca), двери/окна по каталогам систем. Ручная библиотека 20–40 позиций.
2. **Параметрический шаблон категории** по габаритам ИЗДЕЛИЯ (шкаф, диван, кровать, стол, тумба, унитаз, раковина, розетка)
   + текстура CC0 (Polyhaven/ambientCG).
3. **Габаритная коробка** «модель не подобрана» — лист не врёт.
- Габариты из YML-фидов (Яндекс Маркет) — это **упаковка**, для чертежа непригодны; брать из `param` или техлиста.
- Image-to-3D — только декор на рендере; по чужому фото — производное произведение, нужен разрешённый источник.
- Электрика: высоты по нормам (СП 256, ПУЭ). Сантехника: выводы только под утверждённую модель.

## 6. Юридическое (до первого рубля комиссии — юрист)

- **Комиссии на НПД нельзя**: при агентской/посреднической квалификации теряется НПД со дня начала (422-ФЗ ст. 4 ч. 2 п. 5,
  ст. 5 ч. 19). Для комиссий — ИП на УСН или ООО. CPA-сети (Admitad/EPN) работают по оферте, агентский договор нужен только
  при закупке «за клиента», которую не делаем.
- **Реклама (ЕРИД)**: ссылки только в закрытом проекте конкретного клиента. На публичных страницах сайта — без партнёрских ссылок
  (иначе пометка «Реклама», рекламодатель, erid через ОРД).
- **152-ФЗ**: персональные данные клиента магазинам не передаём; в ссылках только обезличенный sub_id.
- **Права**: фото, описания, 3D — только по условиям партнёрки/фида или письменному разрешению; парсинг карточек — нет.
- **Ответственность за габариты**: в спецификации пометка «данные производителя на дату, проверить перед заказом»; ошибку
  перерисовки студия всё равно несёт — отсюда автосверка.
- Раскрытие вознаграждения — в договоре с клиентом и в спецификации отдельной строкой. Платёжных данных не собираем.
