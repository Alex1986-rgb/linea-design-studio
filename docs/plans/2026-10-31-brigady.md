# План: сервис «Ремонт по проекту» (31.10.2026, ветка brigady)

Бригады регистрируются и проходят проверку, клиент с оплаченным проектом LINEA на странице заказа подбирает бригаду,
сравнивает предложения по позициям сметы, выбирает, подписывает договор подряда напрямую с бригадой и принимает этапы.
LINEA — посредник (агентский договор с бригадой), комиссия 7 % со сметы бригады после выбора и подписания договора.
Оплата ремонта — вне сайта; «безопасная сделка» ЮKassa — заготовка.

Решения приняты (см. задачу): 7 %, Москва и МО, проверка ИНН + видеозвонок, сканы паспортов не храним.

1. **Данные и ядро** — `server/api/lib/brig.php`: таблицы `br_*` в той же linea.sqlite, справочники (специализации, районы,
   статусы), сессия бригады (httponly + secure + SameSite=Strict), CSRF (сессия — заголовок X-CSRF; клиент — HMAC от токена
   заказа), лимиты частоты, загрузки (только JPEG/PNG/WebP/PDF, проверка содержимого, пережатие GD, хранение в
   linea-private/brigady/files), журнал действий, комиссия. Письма — `lib/brig-notify.php` (шаблоны, mail(), Telegram-заготовка
   выкл., при test=1 ничего не уходит).
2. **API бригады** — `server/api/brigade/*.php`: auth (регистрация, вход, выход, восстановление по ссылке), profile (анкета,
   объекты «до/после», отправка на проверку), upload/file (загрузка и отдача с проверкой прав), feed (лента обезличенных
   запросов, только допущенным), offer (предложение по позициям, правка до срока), jobs (объекты, контакты после выбора,
   этапы, фото, «готово к приёмке», закрытие замечаний, споры), finance (комиссия, счета, отзывы).
3. **Клиент** — `server/api/remont.php?t=` (подбор с согласием, сравнение, выбор с согласием на передачу контактов, договор
   подписан, приёмка этапов по чек-листам, споры, отзыв) + `remont-dogovor.php` (договор подряда HTML → печать в PDF с
   приложениями). Блок «Ремонт по проекту» на order.html — `site/js/remont.js`. Чек-листы приёмки — из правил технадзора
   GOST-DRAFT (QC-xx, СП 71/73, ПУЭ 1.8), коротко.
4. **Админка** — `server/api/admin-brigady.php` на той же сессии и пароле, что admin.php: модерация бригад (ИНН: контрольная
   сумма, ссылки ФНС, открытый API статуса НПД), допуск/блок с причиной, запросы → автоподбор → рассылка, предложения,
   объекты и этапы, споры, комиссия (счёт, оплата, CSV), модерация отзывов с причиной, журнал админа.
5. **Пакет проекта** — `tools/brigady-pack.mjs`: из project.json GOST-DRAFT позиции сметы (работы) по специализациям и
   ведомости xlsx без ФИО/адреса/телефона клиента; загружается в запрос из админки.
6. **Страницы** — `tools/gen-brigady-pages.js`: `/remont/` (клиентам), `/brigadam/` (бригадам), `/brigada/` (кабинет, noindex),
   черновики noindex «редакция от 31.10.2026, проект»: правила площадки, агентский договор-оферта для бригад, условия для
   клиентов. Одна правка в site-shell.js (разделы в подвале), meta linea-api для brigada/ в site-rebase.js, белый список
   .htaccess.
7. **Проверка** — `tools/dev-router.php` (php -S: site/ + api/), `tools/test-brigady.mjs`: сквозной сценарий (3 бригады →
   допуск 2 → заказ prompt-kv54 → подбор → 2 предложения → сравнение → выбор → договор → 2 этапа (возврат, приёмка) →
   отзыв → комиссия → счёт оплачен) + негативы (без допуска, чужой объект 403, CSRF 403, .php отказ, контакты до выбора).
   Браузер 375/1280, скриншоты docs/reports/img/2026-10-31-brigady-*.jpg.
8. **Отчёт** — docs/reports/2026-10-31-brigady.md: схема данных, роли и права, сценарии, тесты, что не сделано, что нужно от
   Александра. Коммиты частые, только ветка brigady, без push и выкладки.

Ограничение среды: на диске мака свободно ~300 МБ — worktree поднят sparse-checkout без `site/portfolio/` (410 МБ альбомов),
тестовые данные — минимальные.
