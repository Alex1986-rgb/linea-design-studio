# План: «Смета на материалы» как самостоятельная услуга (09.11.2026)

Решения владельца: цена прежняя (TERMS.addons.smeta), свой короткий бриф, оплата до работы, тот же механизм заказа. Чужой проект не проверяем и не исправляем — только считаем материалы.

1. **Модель.** Новый вид заказа `kind = 'smeta'` (LINEA_KINDS + prices.smeta в config — тот же ключ, что у опции; миграция не нужна, `orders.kind` — строка). Сумма = формула сметы. После оплаты заказ получает «основную» строку `order_options` (opt=smeta, source=order) — через неё работают загрузка PDF+таблицы, письмо, скачивание, очередь «Ждут нас». Выдача файлов переводит заказ в `delivered`. Опцию к такому заказу добавить нельзя.
2. **Бриф сметы.** Страница `site/smeta/zakaz/` (генератор `tools/gen-smeta-brief.js`) + `site/js/smeta-brief.js`; приём — `brief.php` с `meta.service = 'smeta'` (те же проверки https/согласия/файлов/test=1/лимитов). Белый список dev-router, мета linea-api в site-rebase.
3. **Сайт.** `/smeta/`: два входа, «что прислать», блок про точность, FAQ, Offer; «или отдельно» на /price/, главной, /faq/, /process/, в каталоге.
4. **Кабинет и админка.** Этапы «Заявка → Оплата → Расчёт → Смета готова»; вкладки без правок и ремонта; письма со своими формулировками; админка — значок вида, фильтр, читаемый бриф сметы, очередь; `order-pull.mjs` — kind и файлы проекта клиента.
5. **Тесты.** Новый шаг в `test-kabinety.mjs`; все прежние зелёные.
6. **Браузер.** `/smeta/`, бриф сметы (оба варианта, до сводки, без отправки на боевой), кабинет — 1280 и 375.
7. **Документы.** CLAUDE.md, отчёт `docs/reports/2026-11-09-smeta-otdelno.md`, коммиты явным списком файлов.
