# Критик техники: LINEA + GOST-DRAFT как одна система — 31.10.2026

Вопрос: выдержит ли система 10–50 заказов в месяц почти без ручного труда. Только чтение кода, документов и живого сайта
(`curl` заголовков и `api/ping.php`); на Beget и SmartApe не заходил, ничего не менял.

**Короткий ответ.** Вычислительно — да с запасом: нагрузочный прогон 27.10 дал 17–18 заказов в час на 2 слотах рядом с Alpine,
50 заказов в месяц — это ~2 в день. **Не выдержат люди и связки:** из 14 шагов заказа 8 ручные или запускаются с мака, мак —
единственная точка для деплоя сайта, синхронизации кода на сервер, `/qa` и выдачи, а на нём **2,6 ГБ свободно (99 %)**. Бэкапов
базы и `linea-private` нет. Сайт LINEA живёт на одном общем аккаунте Beget с пятью другими сайтами — дыра в любом из них
открывает ПДн заказчиков.

## 1. Карта системы

```
 Заказчик (браузер)
   │ бриф ZIP ≤100 МБ, согласие ПДн          правки review.html        обмер /obmer/ (ещё не выложен)
   ▼                                          ▼                         ▼
 Beget, аккаунт aleks2si (общий с konsulcar, gorina, pasika, копией myarredo 41 ГБ, seomarket)
   public_html/api/*.php ──► ../linea-private/  linea.sqlite · orders/<N>/brief.zip+json · reviews/ · surveys/ · rate/ · sessions/ · config.php
   │  admin.php (пароль)  [Р1] сумма → [Р2] «счёт выставлен» → [Р3] «оплачен» (mode=manual, ЮKassa выключена)
   │  (ветка linea-zakazy, НЕ выложено) queue/ pending→claimed→done + api/queue.php (X-Linea-Queue-Token)
   ▼
 SmartApe (Windows, общий с кликером Alpine, OmniRoute, gost-learn)
   linea-bridge loop  [Р4: запускать руками, живёт в ssh-сеансе — не служба]
   → hold/ «ждёт обвода плана» [Р5: дизайнер обводит план; plan-intake — в работе]
   → order-queue worker → order-run: project → full → overlap → full2 → studio → overlap-work → fill → lint → pdf
   → needs-designer  [Р6: подпись дизайнера `gate designer`]  [Р7: /qa — Claude Code на маке, до 3 кругов]
   → визуализации: imgen через router.cheap (вне конвейера) [Р8: отбор и подпись кадров podpis.mjs]
   → deliver.sh --real (запуск с мака через remote.sh; rclone на сервере, токен Диска в SYSTEM-профиле)
       → gdrive:LINEA/Клиенты/<дата>_<слаг>/  [Р9: доступ к папке даёт Александр]
   → 3D: сборка на SmartApe C:\pascal\client-viewer → deploy-3d.sh с мака → 3d.<домен> [Р10: SSL в панели]
   ▼
 admin.php [Р11: «выдан» + ссылка руками] → order.html показывает ссылку
 Правки заказчика → linea-private/reviews/*.json [Р12: разбор и перевыпуск руками — цепочка заново]
```

Ручные шаги (Р): 12, из них **на маке обязательны** Р7 (/qa), запуск выдачи, деплой сайта и 3D, синхронизация кода движка
на сервер (`remote.sh` шлёт рабочее дерево мака — на сервере крутится то, что лежит на маке, вместе с незакоммиченным).

**Единые точки отказа**

| Точка | Что ломается | Сейчас |
|---|---|---|
| Мак Александра (8 ГБ, **2,6 ГБ свободно**) | деплой сайта и 3D, код движка на сервер, `/qa`, запуск выдачи, все секреты | worktree brigady уже пришлось ставить sparse-checkout (свободно ~300 МБ на момент плана) |
| `~/.claude/secrets/*.env` (23 файла открытым текстом) | Beget API, ЮKassa SeoMarket, роутер, пароль admin LINEA, Supabase, Директ… | читает любая сессия и любой субагент любого проекта |

| Аккаунт Beget aleks2si | сайт, база, ПДн, ключ ЮKassa в config.php | один unix-пользователь на 6+ сайтов; квота общая с копией myarredo 41 ГБ / 113 тыс. страниц |

## 2. Надёжность при 10 / 50 заказах в месяц

| Узел | 10 заказов/мес | 50 заказов/мес |
|---|---|---|
| Сборка на SmartApe | ок (208–340 с на заказ) | ок: потолок 17 заказов/ч на 2 слотах |
| Диск SmartApe `C:\gost-draft-out` | ок при `out-clean` | ~0,2–0,5 ГБ на заказ × 50 + PDF + визуализации; `out-clean` запускается руками, боевой корень чистится только с `--with-orders` |
| Деревья на сервере `C:\gost-draft-trees\*` | 12 копий растут | то же; `--prune-trees` руками |
| Утечка временных Chrome | исправлено в ветке (3,6 ГБ за прогон), в main ~4000 `.tmp` | без слияния — гигабайты в неделю |
| Мост и исполнитель | падают с ssh | при 2 заказах в день кто-то должен держать сеанс → **нужна служба** |
| Дизайнер (обвод плана + подпись) | ~1–2 ч на заказ | 50–100 ч/мес — **главное узкое место** |
| `/qa` | 1–3 круга × 4 критика, на маке | 150–600 запусков агентов в месяц — упрётся в лимит MAX и в RAM мака |
| Визуализации | 10–20 кадров × попытки, деньги шлюза | баланс кончится молча; 503 шлюза |
| SQLite на Beget | ок | ок (WAL, BEGIN IMMEDIATE); MySQL — ради brigady, не ради нагрузки |
| Загрузки брифа ≤100 МБ | ок | ~5 ГБ/мес архивов в общей квоте Beget; срок хранения не исполняется кодом |
| SSH/rsync к Beget | рвётся, есть партии и tar-повтор | то же, но деплой — не на пути заказа (очередь — HTTP pull с SmartApe, это правильно) |
| Письма | `notify_enabled=false`, `mail_from` пуст | новый заказ видно только зайдя в admin.php |

**Бэкапы.** Своих нет ни для `linea.sqlite`, ни для `linea-private/orders`, ни для `C:\gost-draft-out\orders`, ни для
токена rclone. Есть только встроенные копии Beget (срок не проверен) и сам Google Диск (выданное). Потеря `linea.sqlite` =
потеря токенов заказчиков, сумм, отметок оплаты и согласий ПДн.

**Мониторинг.** Нет. `api/ping.php` есть, но его никто не опрашивает; `tools/health.mjs` — в ветке studio-system, не в main.
О падении моста, переполнении диска, кончившемся балансе шлюза или 5xx сайта узнаем от заказчика.

**Восстановление.** Не описано и не проверялось: как поднять сайт на другом аккаунте Beget, как перенести очередь и
`linea-private`, как пересобрать заказ после смерти SmartApe (код — на маке и в git, данные заказа — только на сервере).

## 3. Безопасность

Прочитаны `server/api/*` (main), `linea-zakazy` (очередь, контракт), `linea-brigady/server/api/lib/*` (не закоммичено).

**Что сделано хорошо:** данные вне веб-корня; PDO с параметрами везде; сумма к оплате только из базы; вебхук ЮKassa
перепроверяется GET-ом, отметка «оплачен» один раз, сверка суммы и номера; Idempotence-Key; admin — `password_verify`,
`session_regenerate_id`, HttpOnly + SameSite=Strict + Secure, CSRF на каждое действие, CSP, X-Frame-Options; лимиты частоты;
ZIP не распаковывается, проверяются имена; файлы 0600; токен заказа 128 бит, `hash_equals` для токена очереди; мост снимает
`client` из брифа до записи на диск; brigady — тип файла по содержимому + пережатие GD, `use_strict_mode`.

**Находки по убыванию важности**

1. **Общий аккаунт Beget (aleks2si).** LINEA, konsulcar (PHP + SQLite с кабинетами), gorina, pasika, копия myarredo, seomarket —
   один unix-пользователь. Любая загрузка файла/RCE в любом из них читает `linea-private/config.php` (ключ ЮKassa, хэш admin,
   токен очереди) и все брифы. → Отдельный аккаунт Beget под LINEA (или хотя бы под `linea-private` + api).
2. **ПДн уходят туда, где согласие их не называет.** Согласие (раздел 5) перечисляет только Beget, ЮKassa и WhatsApp/почту по
   выбору заказчика. Фактически: адрес объекта и план — на SmartApe (сервер с серой автоматизацией); альбом с адресом — на
   Google Диск (США, трансграничная передача); план БТИ, фото, голос — в router.cheap → модели Gemini/OpenAI (plan-intake,
   story-answers, автосверка). → Дописать получателей и трансграничку в согласие или обезличивать перед шлюзом
   (обрезать штамп БТИ, убирать адрес из кадров), а Диск заменить на выдачу с Beget по токену (как SeoMarket `dl/<token>`).
3. **Срок хранения не исполняется.** Согласие обещает удалить неоплаченный бриф через 3 месяца и всё — через год после
   выдачи; в коде удаления нет (`out-clean --with-orders` — руками, 90 дней, только SmartApe; на Beget — ничего).
4. **Подделка X-Forwarded-Proto.** `linea_https()` верит `HTTPS`/`X-Forwarded-Proto`; Beget делает из поддельного XFP
   `HTTPS=on`. HSTS (max-age=31536000, без includeSubDomains/preload) закрывает повторные визиты, но не первый заход по http.
   Подтверждено: на `/` HSTS есть. → Добавить `includeSubDomains; preload` и подать в preload-список, http→https 301 уже есть.
5. **Обход ограничений по IP.** `linea_ip()` берёт сначала `X-Real-IP`, потом **`X-Forwarded-For` из запроса**. Если nginx Beget
   не перезаписывает XFF при отсутствии X-Real-IP — лимиты брифа, правок и 5 попыток входа в admin обходятся подстановкой
   заголовка. → Брать только `X-Real-IP` (его ставит nginx) или `REMOTE_ADDR`; проверить один запрос с поддельным XFF.
6. **Токен заказа в URL = единственный ключ.** `order.html?t=…` открывает статус, ссылку на альбом, будущий «Ремонт по проекту»
   (выбор бригады, передача контактов, приёмка этапов — юридически значимые действия). Токен уходит в мессенджеры,
   историю, превью ссылок; срока жизни и отзыва нет; `Referrer-Policy` не задан. → `Referrer-Policy: no-referrer`, кнопка
   «перевыпустить ссылку» в admin, для brigady — подтверждение действий кодом из SMS/почты.
7. **Admin без второго фактора**, пароль — открытым текстом в `~/.claude/secrets/linea-admin.env` на маке. Брутфорс ограничен
   per-IP (см. п. 5). → Ограничить admin.php по IP или Basic в nginx не выйдет (CGI) — тогда TOTP; пароль — в связку ключей.
8. **Секреты.** Все ключи всех проектов — в `~/.claude/secrets/` открытым текстом, видны каждой сессии Claude и каждому
   субагенту (включая чужие проекты и fleet-qa). На SmartApe — `C:\gost-draft-secrets` (права Administrators/SYSTEM — хорошо),
   но рядом работает Alpine с прокси. Токен Google Диска — в профиле SYSTEM на том же сервере: доступ ко всему Диску
   Александра. → Отдельный Google-аккаунт/сервисный аккаунт только для выдачи; ключи LINEA — в отдельную папку, которую не
   читают агенты других проектов.
9. **Токен воркера (queue_token).** Сделан правильно (заголовок, hash_equals, ≥32 символов, лимит 30 неверных/ч, только https).
   Но он даёт `files` и полный бриф с контактами всех оплаченных заказов → хранить только на SmartApe, ротация раз в квартал,
   журнал claim-ов по IP; идеально — привязать к IP SmartApe.
10. **Мелочи:** `api/ping.php` публично отдаёт версию PHP, наличие конфига и признаки TLS — закрыть или токеном;
    `delivered_url` без проверки схемы (только admin, низкий риск); `survey.php` **нет в белом списке** `api/.htaccess`
    (`FilesMatch ^(brief|order|…|admin)\.php$`) — после выкладки `/obmer/` форма получит 403 (живой POST уже отвечает 403);
    в brigady схема описана дважды — `brig_db()` с `CREATE TABLE` под SQLite и `migrations.php` под MySQL, разъедутся на
    переезде; `test=1` в запросе снимает требование https и письма — клиентский флаг, оставить только для `linea_local()`.

**Логи с ПДн.** `orders.log`, `pay.log`, `mail.log` — без ПДн (хорошо). Но в базе `orders.ip`, в `surveys/*.json` — IP и адрес,
в событиях — имя автора; при «удалении по отзыву согласия» это всё надо чистить одной командой — её нет.

**Утечки через LLM.** Кроме п. 2: промпты агентов `/qa` и fleet-qa читают проектные JSON с адресами, а сессии Claude Code идут
через DeepSeek-переменные в launchd (память `claude-auto-mode-deepseek-env`) — проверить, что сессии LINEA не уходят в
DeepSeek (Китай) с данными заказчика.

## 4. Сложность и долг

- **Два движка.** `linea-design-studio/engine/` (9 800 строк: generate.js, paper.js, landscape*) живёт ради старых альбомов,
  `tools/album.sh`, `regen-fixtures.js` и 5 агентов LINEA (draftsman, cad-normcontrol, estimator, space-planner,
  brief-analyst), которые правят `engine/generate.js`. Заказы идут только через GOST-DRAFT. → Заморозить: альбомы
  портфолио — как статичные PDF, движок и агентов LINEA удалить (или в `archive/`); ландшафт — перенести, если нужен.
- **Дубли агентов:** 21 агент LINEA + 28 GOST-DRAFT + 9 новых в studio-system; одноимённые роли (normcontrol / cad-normcontrol,
  draftsman ×2, estimator ×2, visualizer ×2). В сессии, открытой не в той папке, вызывается не тот.
- **Ветки и деревья.** gost-draft: 29 веток, 12 рабочих деревьев на маке + 5 `wf_*` от fleet-qa, у каждого — копия на сервере.
  svod опережает main на 92 коммита и не отстаёт — main можно перемотать на svod, но в `~/projects/gost-draft` 12 чужих
  незакоммиченных файлов. studio-system / vizual-auto / ac-rekon отстают от main на 30 коммитов. LINEA: 4 дерева,
  `linea-zakazy` — очередь, 160 файлов разницы с main (−5 743 строки: ветка старая, удаляет из main обмер и пр.) — сливать
  будет больно. `linea-brief` в `~/projects` нет.
- **Сервер исполняет рабочее дерево мака.** `remote.sh` синхронизирует незакоммиченное; боевой исполнитель заказов должен
  работать от тега/коммита main (`git pull` на сервере), иначе правка агента посреди дня меняет сборку заказчика.
- **Что сделать кодом вместо агентов:**
  - нормоконтроль, приёмщик, скептик — уже по сути цифры (`release.js`, studio-lint, overlap, fill); агент-«приёмщик» = скрипт с
    порогами + отчёт; агентом оставить только «практика» по PDF и скептика на правки движка, не на каждый заказ;
  - `delivery`, `beget-ops`, `server-ops`, `storage`, `monitor` (studio-system) — это скрипты/службы, а не агенты;
  - разбор правок заказчика (`reviews/*.json` → лист/помещение/владелец) — детерминированное сопоставление по `file` + координатам;
  - сверка брифа, цены, срока хранения, уборка — cron, не агенты.
- **Конвейер `/qa` до 3 кругов на заказ** — исследовательский режим. Для серийных заказов: правила в движке и тесты,
  агенты — по выборке (каждый 5-й заказ) и на новые типы объектов.

## 5. Целевая архитектура на 3 месяца (минимально достаточная)

```
Beget (ОТДЕЛЬНЫЙ аккаунт LINEA)                SmartApe (служба Windows, код = тег main через git pull)
  статика сайта                                  linea-worker = bridge loop + order-queue worker (--slots=2, idle)
  api: brief, order, pay(+ЮKassa), review,  ◄──── HTTPS pull: claim / status / files  (только IP SmartApe)
       survey, queue, admin(+TOTP)               сборка → PDF/DXF/IFC/xlsx → загрузка выдачи на Beget api/upload (токен)
  MySQL: orders, events, queue, brigady          ночной бэкап: дамп MySQL + linea-private → шифр. архив → Диск/Б2
  выдача: /dl/<token> (как SeoMarket)            health: ping сайта, место на дисках, баланс шлюза, возраст очереди
  cron: срок хранения, письма-сводки                → Telegram-бот Александру (одно сообщение в день + тревоги)
Мак: только разработка. Деплой сайта — тоже со SmartApe (rsync там не через VPN мака) или GitHub Actions→Beget по ключу.
Люди: дизайнер (обвод плана, подпись), Александр (кнопки «в работу»/«выдать» в admin); /qa — выборочно.
```

Принципы: одна база (MySQL Beget), одна очередь (сайт — источник истины, сервер — исполнитель), выдача с собственного
домена, мак выпадает из пути заказа целиком, всё, что запускается чаще раза в неделю, — служба или cron, а не агент.
