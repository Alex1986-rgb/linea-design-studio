## 1. Путь клиента: вход → оплата

**Клики:** главная → «Заполнить бриф» (1) → план (2–3: файл/камера) → картинки (отметить 6–9 или загрузить: 7–10) → слова (1–3, можно голос) → контакты (3 поля + галочка согласия = 5) → «Отправить» (1) → страница заказа. Итого **~18–25 касаний, 5–8 минут**. Это хорошо. Дальше путь ломается.

**Где теряется и чем отговаривает платить:**
1. **Главная** (длинная; hero без результата): человек уходит, не дойдя до цены. Первые 3 экрана говорят «план + пара слов», а дальше 10 блоков объясняют, чем программа проверяет программу.
2. **Портфолио:** у 8 из 9 проектов обложка — лист расстановки мебели, а не интерьер; «предварительно: N вопросов к заказчику» (26 у трёхкомнатной). Клиент видит «открытые вопросы» вместо красоты. Подписанных кадров 13, в одном проекте.
3. **Цена:** 80 000 ₽ минимум, оплата 100 % вперёд, результата «до» нет (платный «первый вариант» вслепую), возврат «до начала работы» — после начала только за вычетом расходов.
4. **Страница заказа без суммы** (если нет площади): «назовём цену в течение рабочего дня» — человек остыл.
5. **Оплата:** «по счёту в WhatsApp» от физлица без ИНН + оферта-«черновик». Для 80–160 тыс. ₽ это стоп.
6. **После оплаты:** первый вариант с красной плашкой «ПРЕДВАРИТЕЛЬНО, по такому комплекту не строят» + контрольный обмер, которого в цене нет. Клиент понимает, что оплатил «черновик» и ещё должен что-то мерить сам.

**Автоматическая монетизация — оценка: «наполовину».** Что работает без переписки: бриф → номер и токен → страница заказа → расчёт суммы (`brief.php`: `linea_price()`) → `pay.php` (ЮKassa) → вебхук `pay-notify.php` → статус «оплачен» → кабинет. Чего нет, чтобы клиент мог оплатить сам:
- включённого режима `yookassa` и реквизитов продавца (юридическая блокировка, не техническая);
- гарантированной суммы (площадь не обязательна → ручной путь);
- уведомления Александру о новом брифе и об оплате: `notify_enabled => false` по умолчанию, `notify_to` пуст. Если так же на боевом — лид лежит в `admin.php`, пока кто-то туда не зайдёт;
- доплат/допродаж: замерщик, дополнительный круг правок, перевыпуск после обмера, «только планировка» (`rd`/`planirovka`/`vizual` = null, значит «называем после брифа» — тоже ручной путь), ремонт по проекту;
- рассрочки/частичной предоплаты (50/50 снизит барьер на 80–160 тыс.);
- автоматической выдачи: «delivered» ставится вручную, ссылка вставляется вручную.

## 2. Путь бригады

Регистрация (`/brigada/#register`) → анкета: форма (НПД/ИП/ООО), ИНН, специализации, районы, опыт, **≥3 объекта до/после, рекомендатели** → сверка ИНН по ФНС + видеозвонок → лента запросов своего района → предложение по позициям (можно «не делаем») → клиент выбирает → контакты → договор подряда напрямую (`remont-dogovor.php`) → этапы с фото и приёмкой → отзыв → 7 % после подписания обеими сторонами.

Что непонятно / останавливает:
- **Курица и яйцо:** заказов для бригад нет, пока нет оплаченных проектов (ни одной оплаты). Бригаде нечего «получить» сегодня; анкета с тремя объектами и видеозвонком — высокий вход ради пустой ленты. Нужна «лист ожидания» в 1 поле (телефон + район) и честное «первые заказы — с декабря», а не анкета на 10 полей.
- На `/brigadam/` нет примера в рублях («смета бригады 900 тыс. → вознаграждение 63 тыс.») и нет цифры потока («сколько запросов в месяц»). Для бригады «7 %» без количества заказов — только расход.
- Предложение «по позициям» понятно с таблицей, но бригады считают «за м²» или «по разделам». Режима «цена за раздел» нет (было в прошлом ревью, п. 4 бригад — не сделано).
- **Дыра антиобхода:** комиссия начисляется, когда «договор отмечен подписанным обеими сторонами». Стороны могут просто не отметить, подписать вне сервиса. Контакты открываются при выборе, значит платформа теряет контроль в момент, когда создаёт ценность. Это ровно то, что в плане от 01.11 названо «откаты не крысили».
- Юридический блокер из итога критиков остаётся: 7 % с бригад на самозанятости (422-ФЗ) — страница `/brigadam/dogovor/` называет это «проект», но кнопка «Зарегистрировать» уже стоит.

Что мотивирует остаться на платформе (сейчас слабо, усилить):
1. **Лист по запросу** — доступен только внутри открытого объекта по договору через платформу. Сильнейший якорь: вынести в заголовок и в первую строку «зачем мне это».
2. **Оплата этапов через платформу** (безопасная сделка/удержание): бригаде — гарантия оплаты, клиенту — защита. Если деньги идут через платформу, комиссия удерживается автоматически, обход теряет смысл.
3. **Гарантийный пакет**: рейтинг, отзывы и значок «проверено» живут только у закрытых через сервис объектов (сейчас так и написано — но не показано, как это приводит заказы).
4. **Повторные заказы:** клиент ушёл в ремонт — бригаде досыпать новые проекты района.
5. DXF для мебельщика + xlsx ведомостей — на `/brigadam/` не упомянуты (было в прошлом ревью, не сделано).
