# Промпты-роли LINEA

Набор системных промптов для языковой модели, которая проектирует, чертит и проверяет рабочую документацию
интерьера (и участка) по российским нормам. Роль задаёт **кто отвечает и по каким нормам**, задача — **что
сделать на этот раз и с какими данными**.

## Состав

```
prompts/
├── README.md
├── roles/
│   ├── _base.md                 общая часть: маркировка [Н]/[П]/[Р]/[?], честность, общий формат ответа
│   ├── chief-engineer.md        ГИП: несущие, перепланировка, мокрые зоны, сети, увязка разделов
│   ├── interior-designer.md     дизайнер-архитектор: зонирование, эргономика, стиль, материалы
│   ├── draftsman.md             чертёжник по СПДС: состав листов, графика, размеры, штамп, масштабы
│   ├── electrical-engineer.md   электрик: зоны ПУЭ, розетки, свет, группы, щит, УЗО, ТП
│   ├── plumbing-engineer.md     ВК/ОВ: водорозетки, уклоны, гидроизоляция, ТП, вентиляция, климат
│   ├── normcontrol.md           нормоконтролёр: реестр замечаний с основанием и адресом
│   ├── estimator.md             сметчик: объёмы от чертежа, ГОСТ 21.110, смета
│   └── landscape-architect.md   ландшафт: СП 53.13330, СП 30-102-99, дендроплан, разбивка, вертикалка
└── tasks/
    ├── 01-komplekt-rabochih-chertezhey.md   полный комплект рабочих чертежей квартиры
    ├── 02-proverka-alboma.md                проверка альбома на соответствие нормам
    ├── 03-planirovochnoe-reshenie.md        планировочное решение по обмерному плану
    ├── 04-plan-elektriki.md                 план электрики
    └── 05-razvertki-sanuzla-plitka.md       развёртки санузла с раскладкой плитки
```

## Как собрать итоговый промпт

**Системный промпт** = `roles/_base.md` + `roles/<роль>.md` (в этом порядке).
**Сообщение пользователя** = `tasks/<задача>.md` с заполненными плейсхолдерами `{{…}}` + выход предыдущей роли.

```bash
# пример: электрик на задаче «план электрики»
cat prompts/roles/_base.md prompts/roles/electrical-engineer.md > /tmp/system.md
sed -e 's/{{кВт}}/15/' prompts/tasks/04-plan-elektriki.md > /tmp/task.md   # плейсхолдеры — любым способом
```

Правила сборки:
1. Одна роль — один вызов модели. Не склеивать несколько ролей в один системный промпт: теряется разделение
   ответственности, и модель начинает сама себе разрешать то, что должен запрещать ГИП.
2. Задача передаётся целиком — каждая роль видит, кто работает до и после неё.
3. Выход роли передаётся следующей **полностью** (разделы «Результат», «Замечания», «Передача»), а не пересказом.
4. Незаполненный плейсхолдер оставлять как есть — роль обязана вынести его в «Вопросы», а не выдумать.
5. Для Claude Code агентов (`.claude/agents/*.md`) текст роли можно вставлять в тело агента; фронтматтер
   (`name`, `description`, `tools`) остаётся от агента.

## Конвейер ролей

```
бриф ─► interior-designer ─► chief-engineer ─┬─► electrical-engineer ─┐
                                             └─► plumbing-engineer ───┴─► draftsman ─► estimator ─► normcontrol
                                                                             ▲                          │
                                                                             └──── замечания ◄──────────┘
                                                                                               │ 0 блокеров
                                                                                               ▼
                                                                                   chief-engineer (к выдаче)
```

- ГИП стоит **дважды**: допуск решения до инженеров и финальная подпись после нормоконтроля.
- Электрик и сантехник работают параллельно по одной утверждённой планировке; их коллизии (розетка у раковины,
  питание ТП и кондиционера, люки) сводит чертёжник, спор — ГИП.
- Нормоконтроль возвращает замечания адресно: оформление — чертёжнику, решения — автору раздела.
- Ландшафтный контур идёт отдельной веткой: `landscape-architect ─► draftsman ─► estimator ─► normcontrol`,
  с ГИПом при наличии построек, сетей и охранных зон.

Соответствие агентам репозитория (`.claude/agents/`): interior-designer ≈ concept-designer + space-planner;
draftsman = draftsman; normcontrol = cad-normcontrol; estimator = estimator; финальная приёмка — cad-acceptance
и chief-architect. Роли chief-engineer, electrical-engineer, plumbing-engineer, landscape-architect агентов пока
не имеют.

## Общие правила, зашитые во все роли

- Каждое требование помечено: **[Н]** норма (документ, пункт — только если точно известен), **[П]** практика,
  **[Р]** решение LINEA, **[?]** источники расходятся.
- Классика различения: розетка 300 и выключатель 900 мм — практика; розетки не выше 1,0 м и выключатели
  0,8–1,7 м — ПУЭ 6.6.30–6.6.31; розетка в ванной только в зоне 3 через УЗО 30 мА и ≥ 0,6 м от проёма душевой —
  норма (ПУЭ 7.1.48, ГОСТ Р 50571.7.701, СП 256.1325800.2016).
- Расчёты по нормам (свет, тепло, гидравлика, прочность) — не делаются, передаются организации с допуском.
- Чертежи LINEA правятся только через движок и перегенерацию.

## Откуда нормы

Материалы репозитория: `docs/cad-canon.md` (канон листов), `docs/kb/02-sheet-rules.md` и
`docs/kb/03-details-and-schedules.md` (нормы и практика по типам листов с пометками [Н]/[П]),
`.claude/skills/cad-drawings`, `docs/drawing-kb/11-grafika-chertezhey.md` (графика 89 чертежей бюро),
`engine/land-validate.js` (ландшафтные проверки). Библиотека
`design-reference-library` (практика 216 альбомов, `rules/rules.json`, 520 требований ГОСТ/СП) при сборке
не читалась — внешний диск был отключён. **При подключённом диске** сверить таблицы ролей с `docs/canon/`,
`docs/norms/` и `rules/rules.json` и дописать недостающие пункты с источниками.

Места, помеченные «сверить по действующей редакции», — это значения, для которых номер пункта или таблицы
не подтверждён материалами: СП 42.13330 (расстояния до деревьев), санитарные разрывы СП 53.13330 раздел 6,
воздухообмены СП 54.13330, температура поверхности тёплого пола СП 60.13330.
