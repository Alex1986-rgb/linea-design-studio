# Рабочий регламент чертёжной части LINEA

**Правила чертежа лежат в `docs/cad-canon.md` — это единственный источник истины.** Прочитай его перед любой правкой листа: там нормативная база (СПДС/ЕСКД с номерами пунктов), общие правила листа, состав альбома, чек-листы по каждому типу листа и нормируемые зазоры.

Этот файл — про порядок работы: чем проверять, куда править, как добавить лист.

## Железные правила

1. **Чертёж правится только через код** `engine/generate.js` + перегенерация. Руками в SVG — никогда: правка теряется на следующем прогоне и ломает фикстуры.
2. **Лист без размера — брак.** Без цепочки размеров, привязки или отметки уровня лист не выпускается.
3. **Ни одной белой плашки с текстом поверх графики.** Только выноска `leader()` по ГОСТ 2.316 или номер позиции с расшифровкой в ведомости на том же листе.
4. **Кегли и толщины — в бумажных миллиметрах**, их пересчитывает `normalizeInk()`. Не подгоняй `font-size`/`stroke-width` под конкретный масштаб.
5. **Штриховки с запасом обрезай `clipPath`**: `contentBox()` не измеряет обрезанное и `<defs>`, иначе лист уедет на ступень мельче по масштабному ряду.
6. **Масштаб — только из ряда** `SCALE_SERIES` (планы и развёртки 1:20…1:200, узлы 1:5…1:20). Новый масштаб добавляется в ряд, а не подгоняется на листе.
7. **Каждый лист знает свой тип** (`data-sheet`) — иначе аудит не сможет применить чек-лист канона.

## Порядок работы над листом

```bash
# 1. снять эталон ДО правки — иначе регрессию на 271 листе поймает только человек
node tools/regen-fixtures.js

# 2. правка в engine/generate.js + перегенерация обоих демо
node engine/generate.js examples/demo-brief.json site/portfolio/demo
node engine/generate.js examples/house-brief.json site/portfolio/dom-120

# 3. три проверки — все обязаны быть чистыми
node tools/audit-sheets.js site/portfolio/demo      # содержание по канону
node tools/lint-sheets.js  site/portfolio/demo      # бумага: A3, кегль ≥ 2,5 мм, перо ≥ 0,18 мм
node tools/regen-fixtures.js                        # что именно изменилось на листах

# 4. посмотреть лист глазами: Chrome headless на SVG тут зависает,
#    поднимай preview_start name=linea-site → http://localhost:8141/portfolio/demo/<путь>.svg

# 5. принять новый эталон, если изменения задуманы
node tools/regen-fixtures.js --update

# 6. если лист заполнен плохо — отладка компоновки
LINEA_DEBUG_FIT=1 node engine/generate.js examples/demo-brief.json /tmp/x | grep FIT
```

## Как добавить новый тип листа

1. Опиши чек-лист в `docs/cad-canon.md` (раздел 4) — что обязательно и по какому пункту норматива.
2. Добавь тип в `RULES` в `tools/audit-sheets.js`: `need` — то, без чего лист брак; `want` — желательное (попадёт в замечания).
3. Напиши `drawFlat*` (сводный лист, каркас `flatSheet()`) или `draw*` (покомнатный, каркас `svgDoc()`).
4. Зарегистрируй лист в `FLAT_SHEETS` или в блоке покомнатных листов — **с типом**: четвёртый аргумент `sheetOut(rel, maker, title, scale, type)`.
5. Поправь `TOTAL_SHEETS`, иначе штамп соврёт число листов (движок предупредит в консоли).
6. Прогони пункты 2–5 порядка работы.

## Примитивы, которые обязаны использоваться

| Задача | Примитив | Почему нельзя руками |
|---|---|---|
| размер | `dimH` / `dimV` | засечки 45°, выступы, метка `data-el="dim"` |
| цепочка размеров | `chainDimH` / `chainDimV` | замкнутость цепи + `data-el="chain"` для аудита |
| отметка на развёртке/разрезе | `levelMark()` | знак 45° + полка (ГОСТ Р 21.101, 5.4.3) |
| отметка на плане | `levelPlan()` | число в рамке, три знака после запятой |
| выноска | `leader()` + `inkMap()` | раскладка по 8 направлениям, не лезет на графику |
| условные обозначения | `flatLegendBox()` | единый вид легенды + `data-el="legend"` |
| номер позиции | квадрат-марка + строка ведомости | помещения — кружок, мебель — квадрат: не путать читателя |
| штамп | `stamp()` / `flatStamp()` | единая основная надпись рисуется в `svgDoc()` |
| мебель на развёртке | `furnOnWall()` + `FURN_H` | высоты фронтов из справочника, а не на глаз |

## Приёмка альбома перед выдачей

- [ ] `audit-sheets` — 0 нарушений канона на обоих демо;
- [ ] `lint-sheets` — 0 листов с нечитаемым кеглем или невидимым пером;
- [ ] `regen-fixtures` — изменения только там, где задумано;
- [ ] «Листов N» в штампе = фактическому числу листов;
- [ ] валидатор брифа без ошибок (если есть — в альбоме появляется документ «Замечания к исходным данным», это нормально, но заказчику нужно объяснить);
- [ ] `./tools/album.sh <папка>` собирает единый PDF; страниц = листы + документы + титул + оглавление;
- [ ] 3–4 листа разных типов просмотрены глазами на HTTP.

Замечания уровня `want` — это бэклог, а не брак; их сводка ведётся в `docs/drawings-roadmap.md`.

## Роли-агенты

- `cad-normcontrol` — нормоконтроль листа или альбома по канону, с указанием пункта норматива и функции движка, где чинить.
- `draftsman` — реализация и правка листов в движке по канону.
- `cad-acceptance` — приёмка альбома целиком перед выдачей заказчику.
